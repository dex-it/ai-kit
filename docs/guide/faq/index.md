## Что такое AI KIT и чем он отличается от Claude Code?

Claude Code - программа Anthropic, в которой вы работаете. AI KIT - каталог плагинов для неё: памятки по стекам, специалисты, команды и инструменты. Без Claude Code каталог не работает, а Claude Code работает и без каталога. Что такое плагин, skill и специалист в самой платформе, объясняет раздел [Основы](/basics/).

## Чем бандл отличается от плагина?

Плагин - единица установки: один специалист, один skill, одна утилита. Бандл - список плагинов под роль; кода в нём нет, его ставит скрипт, перебирая список. Бандл удобен тем, что специалист приезжает вместе со skills, на которые опирается. Подробнее: [Бандлы](/concepts/bundles/).

## Нужно ли ставить всё?

Нет, и лучше не ставить. Включённый плагин добавляет в контекст каждой сессии названия и описания своих skills, агентов и команд, даже если вы его не вызывали. Ставьте набор под свою роль. Оценить стоимость конкретного плагина можно командой `claude plugin details <имя>`. Подробнее: [Как Claude Code подхватывает плагины](/concepts/loading/).

## Для каких стеков есть специалисты и skills?

Кодеры и тестописатели есть для .NET и TypeScript; skills - для .NET, TypeScript, Python ML и инфраструктуры. Общие специалисты (ревью, поиск причины бага, дизайн) не привязаны к языку и берут стек из манифеста проекта. Полный список - в [каталоге](/catalog/).

## Можно ли пользоваться каталогом с другим ассистентом, не Claude Code?

Каталог рассчитан на Claude Code. Работа на других средах в охват каталога не входит: формат плагина и механика skills и субагентов относятся к платформе Claude Code.

## Какая у каталога лицензия?

GPL v3.0. Текст - в файле [LICENSE](https://github.com/dex-it/ai-kit/blob/main/LICENSE).

## Как поставить плагины на Windows?

Через PowerShell-скрипты (`install-bundle.ps1`, нужен PowerShell 5.1 или новее) либо через WSL. Один плагин ставится командой `claude plugin install` одинаково на всех платформах.

## Зачем клонировать репозиторий, если плагины приходят из каталога?

Плагины загружает Claude Code из подключённого каталога. Клон нужен скрипту `install-bundle`: он читает состав бандла из `bundle.json` в клоне и для каждого плагина вызывает установку.

## Нужны ли API-ключи?

Для самих плагинов нет. Учётные данные нужны MCP-серверам, которые подключаются отдельно: как их настроить - в [CREDENTIALS.md](https://github.com/dex-it/ai-kit/blob/main/CREDENTIALS.md), готовые конфигурации - в [mcp/README.md](https://github.com/dex-it/ai-kit/blob/main/mcp/README.md).

## Почему не работает вызов без префикса, например `/self-review`?

Команды плагинов вызываются полной формой `/плагин:команда`: `/dex-self-reviewer:self-review`. Короткое имя без префикса каталог не обещает: платформа даёт его только skills. В сценариях и каталоге все команды записаны полным именем.

## Как предложить изменение?

## Работа с агентами

### Почему агент не задаёт мне вопросов?

Вопросы человеку задаёт команда, а не вызванный ею агент: канал к вам есть только у сессии, в которой вы работаете. Если агенту чего-то не хватило, он возвращает `blocked` или `partial` с названием недостающего, а команда формулирует вопрос. В автономных треках `dex-auto` вопрос по умолчанию тоже становится `blocked`; с флагом `--interactive` агенты спрашивают по ходу. См. [Поток вызова](/architecture/call-flow/).

### Что значат complete, blocked и partial?

Это первое поле выхода любого узла. `complete` - результат получен и проверен. `blocked` - не хватает входа или нужного плагина, причина названа. `partial` - доведено не всё: у каждой открытой находки есть решение «отложено» или «блокирует». См. [Границы объёма и проверяемое «готово»](/practices/scope-done/).

### Когда брать отдельные команды, а когда `dex-auto`?

Отдельные команды дают вам контроль над каждым этапом и подходят, когда вы хотите принимать решения по пути (дизайн, проверка требований, ревью). `dex-auto` стоит брать для задач, которые можно отдать целиком по проверяемому критерию «готово»: тикет с понятным результатом, баг с воспроизведением. Он не пушит без `--pr` и не делает merge. Разбор: [Путь типовой задачи](/scenarios/lifecycle/), [Отдать задачу целиком](/scenarios/auto/).

### Можно ли самому править документы, которые ведут агенты?

Можно и нужно: это обычные файлы в вашем репозитории. Черновики агентов помечены `status: review`; принятые вами (`approved`) обязывают агентов. Выведенное из кода (`derived`) читайте особенно внимательно: это реконструкция, а не слово владельца продукта. См. [Корпус и словарь](/architecture/corpus-glossary/).

### Безопасно ли давать агенту токены и доступ к стенду?

Токены передавайте через переменные окружения с минимальными правами, секреты в чат и репозиторий не попадают, на общем стенде работа идёт в режиме чтения. Подробно: [Секреты и общий стенд](/practices/secrets-stand/).

### Почему ревью что-то пропустило или нашло лишнее?

Проверьте, были ли в запросе ТЗ и граница, на каком коммите шло ревью (head MR), нет ли в запросе просьбы «только критичное» (она срезает охват) и есть ли свод правил проекта. См. [Типичные ошибки](/practices/mistakes/) и [Безопасное ревью](/practices/safe-review/).

## Контекст и стоимость

### Сколько плагин стоит для контекста?

Постоянно в контексте лежат только имя и описание каждого skill, агента и команды; тело загружается при вызове, а детали (`references/`) при чтении. Оценку по плагину даёт `claude plugin details <имя>`, по сессии - `/context` и `/doctor`. Цифры и механика: [Контекст: что и когда загружается](/architecture/context-loading/).

### Почему на полном каталоге часть skills не срабатывает сама?

Описания делят общий бюджет листинга (по умолчанию 1% окна), и при переполнении клиент выбрасывает описания реже всего вызываемых. Ставьте набор под роль и вызывайте нужное явно ([Что поставить](/start/choose/)).

### Какую модель выбрать?

Агенты каталога задают модель сами по характеру работы. Для сессии берите режим по задаче: рутина - `medium`, долгие агентные прогоны с высокой ценой ошибки - выше. См. [Модель и effort](/practices/models-effort/).

### Работает ли каталог с провайдерами, кроме Anthropic API?

Плагины - текст и скрипты, они работают в Claude Code на любом поддерживаемом провайдере. Но алиасы моделей `sonnet` и `haiku` у других провайдеров ведут на версии 4.x, а у Haiku 4.5 нет оси `effort`: поведение агентов может отличаться ([Модель и effort](/practices/models-effort/)).

## Для авторов

### Как написать свой skill, агента, команду, мод?

Раздел [Разработка плагинов](/authoring/) даёт путь от выбора вида до Pull Request по каждому виду, а [Типичные ошибки валидаторов](/authoring/validators/) расшифровывает сообщения проверок.

### Как добавить поддержку нового стека?

Новый стек - это новые skills `dex-skill-<стек>-*` и строка в реестре стеков; агенты не правятся. См. [Загрузка по стеку](/architecture/stack-loading/).

### Откуда берутся числа в каталоге?

Из `marketplace.json` и манифестов плагинов при каждой сборке сайта: [Каталог](/catalog/). На страницах руководства числа сверяет проверка `npm run check:drift`, чтобы они не расходились с каталогом.

### Что значат термины «узел», «трек», «оракул»?

Слова собраны в [Глоссарии](/faq/glossary/).
