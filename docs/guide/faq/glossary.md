Имена сущностей берутся из [словаря каталога](https://github.com/dex-it/ai-kit/blob/main/docs/domain/domain-model.md): одно имя - один смысл. Здесь собрано то, что чаще всего встречается при работе; определения сокращены, а строки, которых в словаре нет, помечены знаком *. Точные формулировки и колонка «не путать с» - в словаре. Платформенные термины Claude Code отмечены «платформа».

## Что устанавливается

| Термин | Значение | Не путать с |
|---|---|---|
| Каталог (маркетплейс) | репозиторий плагинов с манифестом `.claude-plugin/marketplace.json`; единственный источник истины по составу | плагин |
| Плагин | единица установки: манифест `plugin.json` и содержимое по виду | бандл |
| Skill | текст, который платформа загружает в контекст: ловушки или правило процесса | документация API |
| Trap-skill | skill-чек-лист ловушек, тип по умолчанию | process-skill |
| Process-skill | тонкий skill-правило оркестрации; требует регистрации в валидаторе | агент |
| Специалист (агент) | субагент с frontmatter и фазами, работает в отдельном контексте | команда |
| Команда | точка входа, которую вы вызываете как `/плагин:команда` | агент, трек |
| Бандл | набор плагинов под роль; состав в `bundle.json` двумя списками (`includes[]` - профиль роли, `dependencies[]` - подтянутое замыканием) | плагин |
| Утилита | плагин из хуков или обёрток над CLI, без skills и агентов | специалист |
| Мод | плагин, который меняет поведение и интерфейс самого Claude Code кодом на TypeScript | утилита |
| Function hook | функция `($, e, next)` на событие движка; из неё собран мод | хук-команда оболочки |
| Реестр стеков | соответствие «манифест проекта - префикс skills»; общий агент читает его вместо зашитого списка | список skills в агенте |
| By-stack loading | отбор профильных skills агентом по префиксу имени | предзагрузка через `skills:` |
| Замкнутость бандла | каждый артефакт, названный компонентом бандла, едет в нём же | зависимости пакетного менеджера |

## Как идёт работа

| Термин | Значение | Не путать с |
|---|---|---|
| Узел | агент, которого вызывает команда, другой агент или главный поток; его выход читает вызывающий, а не человек | агент, работающий по прямому вызову человека |
| Узел трека | агент плагина, которого вызывает скрипт трека; модель и схему выхода задаёт скрипт | узел |
| Трек | порядок работы зоны: фазы, гейты, состав узлов; исполняется скриптом (в `dex-auto` - `feature`, `bugfix`, `review`) | зона, конвейер |
| Главный поток * | сессия, в которой вы работаете; только у него есть канал к человеку | субагент |
| Фаза | отрезок работы агента или трека как контракт: цель, вход, выход, критерий завершения, гейт | шаг инструкции |
| Handoff | передача работы между узлами: сигнатура входа и выхода | вызов инструмента |
| Статус (`status`) | первое поле выхода узла: `complete`, `blocked`, `partial` | вердикт |
| Режим (`mode`) | `interactive` - оператор в петле; `autonomous` - его нет | право пропустить бизнес-решение, канал к оператору |
| Планка эскалации | требование возвращать невыводимое вызывающему, а не решать самому | право спросить человека |
| Оркестратор | сторона, которая запускает узлы, читает их выход и выдаёт санкции | исполнитель |
| Санкция | разрешение вызывающего на действие, видимое вне прогона, или на приёмку артефакта: поле входа (`publish`, `apply`, `deploy`, `approve`, `revoke`) либо команда оператора | режим (санкции не даёт), апрув себе |
| Остановка оператора | точка маршрута, где работа ждёт решения человека | гейт (его исполняет инструмент) |
| Гейт | условие перехода к следующей фазе; hard блокирует, soft фиксирует и идёт дальше | остановка оператора |
| Цель (`TASK`) * | одна задача `dex-auto`: что должно стать иначе, критерий «готово», граница | тикет |
| Ledger (журнал) | состояние цели вне рабочего дерева: файл цели, ход трека, реестр находок | журнал решений |
| Стоп-линия | граница автономии `/auto`: push, деплой, миграции данных, удаление вне рабочего каталога и запись в чужой MR без `--post` не выполняются без санкции; прогон называет стоп-линию поимённо | остановка оператора (там развилка решения, здесь необратимость действия) |
| Журнал решений (decision-log) | решения, принятые вместо оператора, с основанием | ledger |
| Тир | модель исполнителя: `haiku`, `sonnet`, `opus` | уровень effort |

## Качество и проверка

| Термин | Значение | Не путать с |
|---|---|---|
| Оракул | skill вида `{тип}-quality`, который судит готовый артефакт названного типа | ревьюер-агент, норматив этапа |
| Вердикт | исход суда над артефактом: `passed`, `failed`, `unverifiable` | вердикт ревью |
| `quality-checks` | метка рядом с артефактом: что судили, чем и с каким вердиктом; ставит судья, не автор | `self-check` |
| `self-check` | самоконтроль автора до суда; вердиктом не является | метка судьи |
| Вердикт ревью | итог ревью изменения: `APPROVE`, `REQUEST_CHANGES`, `NEEDS_DISCUSSION` | вердикт оракула |
| Находка | дефект, техдолг или улучшение с якорем в коде, сутью и severity; снимается проверкой по коду, а не ответом автора («замечание» - то же на входящей стороне) | претензия без якоря |
| Severity * | серьёзность находки по последствию | приоритет задачи |
| Фальсификация * | попытка опровергнуть находку или гипотезу до доклада | повторное чтение своего вывода |
| Проба готовности | чтение готового набора требований в чистом контексте глазами реализатора: что пришлось бы решить самому | ревью качества набора (`requirement-set-quality`) |
| Домысел | место набора или черновика цели, допускающее две реализации с разным наблюдаемым исходом, мерой или границей | находка (дефект названной единицы) |
| Выводимое / невыводимое | следует ли решение из пришедшего материала; невыводимое возвращается вызывающему | |
| Различающая сила теста | тест красный на дефекте и зелёный на живом коде | покрытие |
| Дельта * | изменения с прошлой ревизии; повторное ревью судит только их | полный разбор |
| Принуждение | чем правило удерживается: инструментом, ревьюером вручную либо ничем при заявленной норме | severity находки |
| Дрейф * | расхождение текстов между собой и с каталогом; ищет `npm run check:drift` | версия |

## Документы

| Термин | Значение | Не путать с |
|---|---|---|
| Корпус проекта * | документация проекта, которую ведут агенты; раскладка в `.docs_layout` | документация задачи |
| Уровень артефакта | 0 - продукт, 1 - фича, 2 - реализация, 3 - код и тесты | зона |
| Зона | область работ со своим порядком (продукт, требования, дизайн) | уровень |
| BRD | документ бизнес-требований; продукта (уровень 0) или фичи | PRD (отдельного нет) |
| `BR`, `UC`, `FR`, `NFR`, `AC` | цель стороны, сценарий, правило поведения, мера качества, критерий приёмки | задача трекера |
| ADR | запись принятого архитектурного решения (формат MADR) | дизайн-документ |
| SAD | архитектурное описание системы по ISO/IEC/IEEE 42010 в форме arc42 | ADR |
| Конституция * | инварианты (`INV`) и сквозные меры (`NFR-P`) продукта | CLAUDE.md |
| Свод правил проекта | правила (`RUL`), выведенные из истории ревью, с якорем на источник | CLAUDE.md |
| Принятость | `status` документа: `draft`, `review`, `approved`, `archived` | проверенность, статус исхода узла |
| Фиксация истины * | запись сделанного в корпус той же веткой, что и код | коммит |

## Платформа Claude Code

| Термин | Значение |
|---|---|
| Контекст | то, что модель видит в данный момент: сообщения, листинг, загруженные тексты |
| Листинг | имена и описания доступных skills, агентов и команд в контексте на каждом ходу; ограничен бюджетом |
| Субагент | агент в своём контексте, запущенный инструментом `Agent` |
| Предзагрузка | полный текст skill из `skills:` во frontmatter агента; грузится при запуске агента |
| Слэш-команда | вызов `/плагин:команда`; полная форма обязательна для команд плагинов |
| Хук | команда оболочки, запускаемая на событие клиента (`SessionStart`, `Stop` и другие) |
| `CLAUDE.md` | файл постоянных договорённостей проекта, читается каждой сессией |
| MCP | протокол подключения внешних серверов-инструментов к модели |
| Effort | уровень рассуждения: `low`, `medium`, `high`, `xhigh`, `max`; набор зависит от модели |
| Область установки (scope) | `user`, `project`, `local`: где записан плагин |
| Worktree | отдельная рабочая копия ветки; на одну цель - один worktree |

Первоисточник по платформе - [документация Claude Code](https://code.claude.com/docs/en/overview); как каталог её использует - раздел [Основы](/basics/).
