Агенты каталога не только пишут код: они ведут требования, дизайн, ADR и планы. Чтобы результат работы нескольких агентов складывался в одно целое, у документации есть карта: что за артефакт, на каком уровне, где лежит и кто его судит. Это **корпус проекта**. Нормативная карта - [CORPUS.md](https://github.com/dex-it/ai-kit/blob/main/docs/CORPUS.md); страница объясняет её на примере.

## Три носителя - не смешивать

| Носитель | Где | В git | Что хранит |
|---|---|---|---|
| Корпус проекта | по ключам файла `.docs_layout` | да | принятое: требования, ADR, дизайн, планы, уровень 0 |
| Документация задачи | `docs/<TASK>/` | да, едет с MR | рабочие документы одной задачи |
| Журнал (ledger) | каталог конфигурации Claude Code, вне рабочего дерева | нет | состояние цели `/dex-auto:auto`: файл цели, ход трека, реестр находок |

Смешение даёт два сбоя: служебное состояние утекает в MR либо документация задачи пропадает вместе с рабочей средой. Журнал `dex-auto` поэтому лежит вне репозитория.

## Четыре уровня артефакта

| Уровень | Что | Пример команды |
|---|---|---|
| 0 - продукт | BRD продукта, доменная модель, конституция | `/dex-business-analyst:product` |
| 1 - фича | цели, сценарии, правила и меры, истории с критериями приёмки | `/dex-business-analyst:feature` |
| 2 - реализация | дизайн-документ, ADR, API-спеки, план реализации | `/dex-architect:design` |
| 3 - код и тесты | код, тесты, миграции, конфиги | `/dex-implement:implement`, `/dex-test:test` |

Признак уровня 0 проверяемый: единица переживает удаление любой одной фичи. Не переживает - это уровень 1. Свод правил проекта на этой лестнице не стоит: он описывает инженерную практику репозитория и ведётся своей командой `/dex-rulebook-miner:rulebook`.

Номер несёт только уровень артефакта, зона (область работ со своим порядком) номера не имеет.

## Где что лежит в вашем проекте

Раскладку задаёт файл `.docs_layout`, в котором ключи (`root`, `product`, `domain`, `adr`, `specs`, `plans`, `rulebook` и другие) указывают на каталоги. Агенты адресуют документы по ключу, а не по зашитому пути: так один и тот же агент работает в проекте с любой раскладкой. Если корпус уже занят, раскладку диктует он: каталог и форма имени берутся с образца. Дефолтное дерево включается только там, где выбирать не из чего: корпус пуст либо класса документов ещё не было.

Нет ключа `product` или `domain` - уровень 0 в проекте не заведён. Это отличается от «пути не найдены»: агент называет отсутствие строкой выхода и работает без него. `/dex-auto:onboard` как раз заводит корпус и уровень 0 для нового проекта.

## Каждый артефакт судит не его автор

Для типов артефактов есть оракулы качества - skills вида `{тип}-quality`: `requirement-quality`, `requirement-set-quality`, `adr-quality`, `design-quality`, `plan-quality`, `api-spec-quality`, `rulebook-quality`. Судья ставит рядом с артефактом метку `quality-checks` с вердиктом `passed`, `failed` или `unverifiable`. Тип без оракула закрывается `unverifiable` с причиной, а не молчанием. Принцип «автор себе не судья» поэтому не зависит от добросовестности: его держит контракт стыка.

Если проверка неприменима, это пишется явно: `n/a` с причиной, «нет данных» с номером открытого вопроса, `unverifiable`. Молчание считается дефектом. Полный список статусов - в CORPUS.md, раздел «Статусы вместо молчания».

## Словарь и конституция каталога

У самого каталога тоже есть уровень 0, и он лежит в `docs/`:

| Документ | Что хранит |
|---|---|
| [Словарь](https://github.com/dex-it/ai-kit/blob/main/docs/domain/domain-model.md) | одно имя - один смысл: для каждого термина значение, синонимы со статусом (`канон` или `к вытеснению`), дом нормы и «не путать с» |
| [Конституция](https://github.com/dex-it/ai-kit/blob/main/docs/domain/constitution.md) | инварианты каталога `INV-NNN` и сквозные меры `NFR-P-NNN` |
| [BRD](https://github.com/dex-it/ai-kit/blob/main/docs/product/brd.md) | цели каталога |

Правило для авторов: имя сущности берётся из словаря, новое имя заводится строкой в словаре тем же изменением, которое его вводит. Имя со статусом `к вытеснению` в новом тексте - дефект, его ловит `ousted-name`. Перечень заведённых имён лежит в стартовом контексте сессий репозитория (`.claude/rules/terminology.md`) и генерируется из словаря командой `npm run sync:terminology`.

Для пользователя каталога словарь удобно читать как глоссарий; краткая версия с платформенными терминами - на странице [Глоссарий](/faq/glossary/).

## Чем это важно в работе

- Вы можете читать и править документы корпуса сами: агенты ведут их как обычные файлы, статус `review` у черновика, `approved` у принятого человеком; принятые обязывают агентов.
- Документ, выведенный агентом из кода (`origin: derived`), - реконструкция, а не слово владельца продукта. Читайте такие документы внимательнее.
- Регулярные правки корпуса идут той же веткой, что и код: к слиянию документация описывает то, что сливается (фиксация истины в `dex-auto`).
