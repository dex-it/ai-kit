Две независимые оси определяют, сколько стоит и насколько хорошо работает агент: **модель** (кто считает) и **effort** (сколько думает). Нормативный документ - [AGENT_FRAMEWORK.md, «Стоимость: model и effort»](https://github.com/dex-it/ai-kit/blob/main/docs/AGENT_FRAMEWORK.md#стоимость-model-и-effort); страница объясняет логику и показывает, как каталог ею пользуется.

## Критерий: тип работы, не тема

Тяжёлая тема (Kubernetes, EF Core) не требует тяжёлой модели, если работа сводится к применению правил. Лёгкая на вид задача (триаж причины сбоя) требует сильной, если нужно открытое суждение. Поэтому тир выбирается по характеру суждения:

| Тир | Когда | Примеры из каталога |
|---|---|---|
| `opus` | высокая цена ошибки, открытое суждение: оркестрация, калибровка severity, фальсификация гипотез, архитектура с компромиссами, многошаговый поиск причины | ревью (семь из восьми агентов группы ревью), архитекторы, `debugger`, `bug-fixer`, `incident-investigator` |
| `sonnet` | основная масса: кодогенерация по правилам, структурированная генерация, диагностика по чек-листу, работа со skills-ловушками | остальные специалисты |
| `haiku` | узкая шаблонная работа без правок кода и без суждения: заполнение по форме, чтение статуса | в каталоге пока не назначен ни одному агенту |

Состояние каталога по замеру `npm run measure:context` на коммите `03456dd9`: 19 агентов на `opus`, 45 на `sonnet`, 11 без `model` - все они узлы автономных треков `dex-auto`, модель которых задаёт скрипт трека. `haiku` не назначается «по ощущению»: условие - узкая шаблонная работа без skills-ловушек и правок кода, плюс замер.

## Цена считается ходами

Дешёвая модель на многошаговой работе часто делает лишние итерации (неверный подход, откат, вторая попытка) и выходит дороже дорогой, закрывшей работу с первого раза. Отсюда правило: **экономить тир там, где работа механическая** (форма, перенос, чтение статуса), а не там, где она просто «неглавная».

В замерах каталога это видно на небольших числах: в опыте с банком фактов на задачах, зависящих от этих фактов, средняя модель с фактами тратила в среднем 2,9 хода, а без них 6,8, и стоимость ячейки росла примерно на половину при том же тире ([Контекст](/practices/context/)). Это пример лишних ходов без нужного факта; сравнения «текст против смены тира» в стенде нет.

## `model` - потолок, `effort` - override

Это главное различие осей, оно определяет, когда что ставить:

| | `model` во frontmatter | `effort` во frontmatter |
|---|---|---|
| Что делает | задаёт модель агента; приоритетнее модели сессии | задаёт уровень рассуждения, пока агент активен |
| Относительно выбора пользователя | удешевляет, потолок пользователя не поднимает | перебивает выбор сессии в обе стороны |
| Правило | всегда явное значение, не `inherit` | вниз (`low`, `medium`) для механики; не ставить для открытого суждения; вверх (`xhigh`, `max`) только с причиной в теле |

Почему асимметрия: `effort: xhigh` у агента на сессии с `low` делает работу дороже, чем пользователь выбрал осознанно, и молча перебивает его выбор. Поэтому «вверх» требует записанной причины, а при сомнении `effort` не ставят - наследование безопаснее неудачного override.

Уровень подбирается прогоном на реальных задачах агента, а не копируется у соседа: порог, ниже которого падает качество, у разных работ разный. При смене модели подбор повторяется, потому что уровни 5.5 перекалиброваны.

## Что нужно знать про платформу

(сверка нормативного документа каталога с документацией Claude Code и Anthropic API, 26-27.10.2026)

- Алиасы `sonnet` и `haiku` ведут на модели 5.5 только на Anthropic API; у других провайдеров они ведут на версии 4.x. Замена `sonnet` на `haiku` вне API даёт Haiku 4.5, у которого оси `effort` нет.
- Ось `effort` есть не у всех моделей: Haiku 5.5 в перечне есть, Haiku 4.5 и ранее нет. Полный идентификатор модели без оси вместе с `effort` валидатор отклоняет (`frontmatter-effort-unsupported-model`); алиас он не судит, провайдер ему не известен.
- Haiku 5.5 на `low` в длинном агентном промте чаще пропускает поиск и проверку и останавливается рано.
- Thinking агент не выбирает: субагент наследует его от сессии, своего поля нет. Просьба «думай меньше» в тексте уровень рассуждения не заменяет.
- Оркестратор, который спавнит подчинённого, назначает ему тир явно: наследование даёт две ошибки сразу - дешёвая сессия роняет тир у судьи, дорогая гонит на Opus заполнение формы.
- В Claude Code `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` перебивает и `model` агента, и параметр вызывающего.

## Что в каталоге решено и что ждёт

| Решение | Статус |
|---|---|
| Явный `model` у каждого агента, `inherit` не используется | действует, проверяет валидатор |
| 11 узлов `dex-auto` без `model`: тир задаёт скрипт трека | осознанное исключение |
| У пяти узлов `dex-auto` модель не задана и в скрипте (наследуют сессию) | зафиксировано как находка; менять без прогона нельзя |
| `effort` во frontmatter | один агент (`doc-writer`, `medium`); остальные наследуют |
| Понижение `opus` до `sonnet` у части агентов (кандидаты названы) | ждёт замера «пара тир против тира» |
| Назначение `haiku` агентам-кандидатам | ждёт замера и учёта алиаса у провайдеров |

Замер для этого ещё не проведён: готовых наборов «агент x задача» в стенде нет, их нужно собрать, а прогон платный. Оценка по ценам стенда: набор из 12 агентов, двух задач на агента и трёх тиров при трёх повторах (216 ячеек) стоит порядка 11-15 долларов. Источник: [claude55-models.md](https://github.com/dex-it/ai-kit/blob/develop/docs/migration/claude55-models.md) (временный документ миграции).

## Практика для вас как пользователя

- Для обычной работы не переопределяйте `effort` в плагинах: он осознанно наследуется от сессии. Режим сессии выбирайте по задаче: `medium` для рутины, выше для долгих агентных прогонов, где цена ошибки высока.
- Если расход велик, сначала проверьте контекст (`/context`, `/doctor`: [Контекст](/architecture/context-loading/)), потом число лишних плагинов, и только потом тир.
- Если вы пишете свой агент: выберите тир по характеру суждения, `effort` не ставьте без причины, зафиксируйте причину в теле, если ставите вверх ([Писать агента](/authoring/agent/)).
