`description` - единственное, что модель видит о единице до её вызова. Skill, агент и команда выбираются по нему, поэтому плохое описание делает хорошую единицу мёртвой. Нормативные документы: [SKILL_FRAMEWORK.md](https://github.com/dex-it/ai-kit/blob/main/docs/SKILL_FRAMEWORK.md#правила-для-description-семантическая-активация) и [AGENT_FRAMEWORK.md](https://github.com/dex-it/ai-kit/blob/main/docs/AGENT_FRAMEWORK.md#description-семантическая-активация).

## Два разных текста

У плагина два жанра описания, и смешивать их нельзя:

| Жанр | Где | Кому адресован | Чем отличается |
|---|---|---|---|
| **Поле срабатывания** | `description` во frontmatter skill, агента, команды | модели, которая выбирает единицу | роль плюс активаторы и симптомы; лежит в контексте постоянно |
| **Витрина** | `description` в `plugin.json` | человеку в списке `/plugin` | по-русски, по телу плагина, без слов-триггеров |

Скопировать одно в другое - ошибка в обе стороны: витрина, набитая триггерами, хуже обеих. Из 201 плагина на проверке нашлись два нарушения, оба - копии поля срабатывания в витрину. Дом витрины - `plugin.json`, каталожная копия генерируется (`npm run sync:marketplace`).

## Формулы по видам

**Skill:** `<Технология> - <ключевые аспекты в одном предложении>. Активируется при <якорь>, <аспект 1>, <аспект 2>, ...`.

- Якорь технологии обязателен (`ef core`, `RabbitMQ`, `DDD`).
- Активаторы - **аспекты**, то есть темы уровня раздела; конкретные API и симптомы внутри одной ловушки (`OwnsOne`, `cache miss`) - точки входа, они срабатывают только на буквальное совпадение и шумят. Активатор под одну ловушку удаляйте.
- Тема шире одного инструмента - якорь по теме, не по вендору («Logging», а не «Serilog logging»).
- Не меньше 10 активаторов; нужен текст «Активируется при».

**Агент:** `<Роль> - <области ответственности>. Триггеры - <симптомы>, <названия областей>`, плюс сжатая сигнатура handoff.

- Симптом - то, с чем приходит пользователь до понимания причины: «у меня NRE», «не работает».
- Не писать названия фаз, имена skills и инструментов, перечень всех ловушек, общие слова без домена.
- Если места не хватает: сжимайте сигнатуру, активаторы держите - без них агент не выбирается.

**Команда:** одно короткое предложение, различимое от соседей. Команды стоят в том же листинге, что и skills, и безусловно: у каталога медиана описания команды около 66 знаков.

Про выбор слов:

- **Первая фраза несёт роль.** У реальных соседей различие лежит в первых словах («Первичное ревью» и «Ре-ревью»), а хвосты триггеров почти всегда общие. Пара, разведённая только хвостом, - кандидат на правку: роль (пишет, судит, исполняет, хранит норму) ставится в начало.
- **Хвост соседа не копируется дословно.** Две из семи реальных пар каталога делят хвост триггеров почти слово в слово (skill и его исполнитель, оркестратор и его исполнитель). Когда единицу вызывает другая единица по имени, её описание сообщает про вызов (вход и выход), а не про пользовательский запрос.
- **Не используйте угловые скобки** `<` и `>`: клиент показывает их как `&lt;` и `&gt;`; для заполнителей есть `argument-hint`.
- **Точное число внутренних единиц не пишется** («семь фаз»): оно дрейфует в трёх копиях. Пишите форму: «многофокусный скан».
- **Ключевое слово - в начале.** Запись режется по хвосту.

## Пределы длины

| Что | Skill | Агент | Команда |
|---|---|---|---|
| минимум | 50 знаков | 50 знаков | нет |
| ориентир | до 500 (больше - предупреждение) | до 500 (больше - предупреждение) | нет порога |
| потолок каталога | 750 (ошибка) | 750 (ошибка) | нет |
| потолок платформы | 1536 на `description` + `when_to_use`, дальше обрезка | не документирован | - |

Меняйте `description`, только когда меняется то, с чем придёт пользователь: новый класс задач, новый стек, смена роли. Новая фаза или новый skill в фазе описание не меняют.

## Почему коротко: бюджет листинга

Описания всех доступных единиц делят общий бюджет (по умолчанию 1% контекстного окна). При нехватке клиент выбрасывает описания целиком, начиная с редко вызываемых, а skill без описания автоматически не срабатывает. Цифры и механика - [Контекст: что и когда загружается](/architecture/context-loading/). Следствие для автора: лишние активаторы отнимают место у соседей по всему каталогу, поэтому при нехватке места режут точки входа, а аспекты оставляют.

## Что измерено про выбор из большой библиотеки

Вопрос: ухудшается ли выбор единицы, когда в листинге сто skills вместо десяти. Что известно (опыты стенда `eval55` и пилот к ним):

- Полная серия опыта о росте библиотеки (E7) **не проведена**: решено ставить её только после набора «жёстких соседей» с реальными парами из каталога.
- Пилот на небольшой модели (20 кейсов, библиотеки в десять и в сто skills, по три повтора) деградации **не показал**: доля верных выборов при ста skills была 0,98 против 0,90 при десяти. Разность в пределах шума выборки, знак обратный ожидаемому, поэтому это не доказательство улучшения, а отсутствие свидетельства ухудшения на текущем каталоге.
- Лексически похожих описаний в каталоге мало: порог близости 0,40 прошли 64 пары из 41 041, и почти все объяснимы (команда и её агент, соседние команды одного CLI). Реальную путаницу нашли у семи пар, где совпадают хвосты триггеров.

Отсюда практика: не бойтесь большой библиотеки, но разводите соседей по роли, а при добавлении единицы проверьте, не повторяет ли её описание хвост соседа. Источники: [claude55-descriptions.md](https://github.com/dex-it/ai-kit/blob/develop/docs/migration/claude55-descriptions.md) (временный документ миграции, после слияния выводов может быть удалён) и [предварительная регистрация стенда, итоги пилота](https://github.com/dex-it/ai-kit/blob/develop/tests/eval55/PREREG.md#что-показал-пилот).

## Проверить

```bash
npm run measure:listing              # бюджет, пары похожих описаний
node tools/description-listing.js --pairs=0.4
npm run test:activation:agents       # платный: видимость агента
```

Первые две команды бесплатны и ничего не блокируют, это измерения. Проба активации (`tools/run-activation.js`) гоняет живую модель и в CI не входит. Для правок формулировок «а выберут ли?» нет замены прогону: по описанию это не видно, и поэтому нормативные документы требуют свидетельства, а не ощущения.

## Чек-лист

- [ ] жанр верный: поле срабатывания и витрина не скопированы друг в друга
- [ ] первая фраза называет роль или технологию, а не процесс
- [ ] активаторы - аспекты, их достаточно, нет точек входа одной ловушки
- [ ] нет номеров фаз, имён инструментов и skills, угловых скобок
- [ ] описание не повторяет хвост соседа дословно
- [ ] длина в пределах; ключевой смысл в начале
