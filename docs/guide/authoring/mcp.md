MCP-серверы - не плагины каталога, а внешние процессы, через которые модель получает инструменты для системы (трекер, база, браузер). Каталог хранит **шаблон** подключения: готовые описания серверов, переменные окружения и инструкции. Источники: [mcp/README.md](https://github.com/dex-it/ai-kit/blob/main/mcp/README.md) и [CREDENTIALS.md](https://github.com/dex-it/ai-kit/blob/main/CREDENTIALS.md).

## MCP или CLI-утилита

| Сценарий | Что выбрать | Почему |
|---|---|---|
| read-only диагностика («покажи поды», «объясни запрос») | **CLI-утилита** | одна команда, нет сервера, малый радиус поражения, используется авторизация существующего CLI |
| быстрая проверка в отладочной сессии | CLI | быстрее, вывод сразу в разговоре |
| длинный автономный сценарий по одной системе | **MCP** | структурированная схема инструментов, многошаговые вызовы |
| нужна запись в систему через Claude | MCP с явной границей авторизации | CLI-плагины каталога read-only, кроме двух диагностических `/dex-kaf-cli:kaf-produce` и `/dex-rabbitmqadmin-cli:rmq-publish` |
| общий доступ нескольких агентов к одной базе или кластеру | MCP | центральная авторизация и аудит |

Матрица в нормативном виде: [CLI_UTILITIES.md, «CLI vs MCP»](https://github.com/dex-it/ai-kit/blob/main/docs/CLI_UTILITIES.md#cli-vs-mcp-матрица-решений). Общий выбор между видами исполнителя: [Skill, агент, команда, мод или MCP](/practices/choose-executor/).

## Шаблон `mcp/mcp-template.json`

В шаблоне 24 сервера: документы и трекеры (Notion, Atlassian, Google Drive, PDF), VCS и CI (GitHub, GitLab, TeamCity), базы (через `genai-toolbox`), очереди и логи (RabbitMQ, Kafka, Seq), контейнеры (Docker, Kubernetes), браузер (Playwright, Chrome DevTools), мониторинг (Grafana, Sentry), ML-инструменты.

Запись сервера выглядит так (сервер GitHub из шаблона):

```json
"github": {
  "_description": "GitHub - repositories, issues, pull requests, actions",
  "_env": ["GITHUB_TOKEN"],
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-github"],
  "env": { "GITHUB_TOKEN": "${GITHUB_TOKEN}" }
}
```

| Поле | Назначение |
|---|---|
| `_description`, `_env`, `_note` | подсказки для человека; при копировании в `.mcp.json` проекта **удаляются** |
| `command`, `args` | как запускается сервер (`npx`, `uvx` или бинарь в `PATH`) |
| `env` | переменные окружения, значения берутся из вашего окружения подстановкой `${VAR}` |

## Подключить сервер к проекту

1. Откройте `mcp/mcp-template.json`, скопируйте нужные серверы в `.mcp.json` вашего проекта и удалите остальные, а также поля `_description`, `_env`, `_note`.
2. Задайте переменные окружения в `.env` (образец - `run-claude/sample.env`) или в профиле оболочки.
3. HTTP-серверы в `.mcp.json` не копируются: их регистрирует скрипт `run-claude/register-http-mcp.sh` (на Windows - `.ps1`). Сначала `--dry-run`: он покажет команды со скрытыми токенами.
4. Запустите `claude` и проверьте командой `/mcp list`. Если сервер не запускается: проверьте переменные, запустите `claude --mcp-debug`, убедитесь в наличии `npx`, `uvx` или бинаря.

Для серверов на `npx` нужен Node.js, на `uvx` - `uv`, `kafka` и `seq` ставятся отдельными бинарями.

### Синтаксис переменных

| Запись | Смысл |
|---|---|
| `"${VAR}"` | сервер без неё бесполезен; **незаданная переменная не останавливает загрузку**: серверу уходит сам текст `${VAR}`, а `claude mcp list` печатает предупреждение |
| `"${VAR:-значение}"` | необязательная со значением по умолчанию |
| `"${VAR:-}"` | необязательная с пустым значением |

Форма `${VAR:-}` обязательна для взаимоисключающих переменных (Cloud и Server/DC в записи `atlassian`): голая форма доставила бы серверу текст `${VAR}`, и он счёл бы продукт включённым с мусорными значениями.

## Секреты: что делать и чего нет

Токен MCP-сервера - обычный секрет, и правила те же, что для любых ключей ([Секреты и общий стенд](/practices/secrets-stand/)):

- токены только в переменных окружения, значения не пишутся в `.mcp.json` и в репозиторий; `.env` в `.gitignore`;
- минимум прав у токена, срок действия, отдельные токены для dev и prod, у каждого разработчика свои;
- значение секрета можно брать из менеджера паролей прямо в `run-claude/.env` (подстановка `$(pass show <путь>)`);
- Claude Code хранит токен MCP открытым текстом в любой области (`~/.claude.json` или `.mcp.json`), поэтому при области `project` файл с токеном добавляют в `.gitignore`.

## Добавить сервер в шаблон каталога

Для вклада в каталог (шаблон не проверяется валидаторами, поэтому ответственность на авторе и ревью):

1. Добавьте запись в `mcp/mcp-template.json`: `_description`, `_env` с перечнем переменных, `command`/`args`/`env`; необязательные переменные оформляйте `${VAR:-}`.
2. Опишите сервер в `mcp/README.md` (раздел по группе), добавьте переменные в `run-claude/sample.env` и порядок получения токена в `CREDENTIALS.md`.
3. Проверьте JSON (`node -e "JSON.parse(require('fs').readFileSync('mcp/mcp-template.json','utf8'))"`) и запуск сервера на чистом профиле.
4. Если у системы есть зрелый CLI, рассмотрите сначала CLI-утилиту: она легче и не создаёт ещё одну поверхность секретов ([Плагин и бандл](/authoring/plugin-bundle/), [Писать команду](/authoring/command/)).

Плагины каталога не регистрируют MCP-серверы сами: это разовая операция пользователя, и лаунчер `run-claude` их тоже не регистрирует.
