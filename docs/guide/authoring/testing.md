Проверки каталога делятся на три слоя: **бесплатные и обязательные** (входят в `npm run precheck` и CI), **бесплатные справочные** (измерения), **платные** (живые прогоны моделей, вручную). Начните с первого слоя, остальные включайте по предмету правки. Схема гейта: [Цепочка проверок](/architecture/validation-chain/); команды перед коммитом: [Проверки перед коммитом](/contributing/checks/).

## Слой 1: обязательный гейт

```bash
npm ci
npm run precheck
```

`precheck` объединяет:

| Часть | Что проверяет | Когда падает |
|---|---|---|
| `npm run validate` | валидаторы форм: агенты, skills, команды, бандлы, контракт стыка, витрина README, реестр правил, терминология, синхронность словаря и треков, типы модов | нарушена форма файла или согласованность каталога |
| `npm test` | сами правила валидаторов на фикстурах | правило перестало срабатывать на заведомом дефекте или фикстура не соответствует ожиданию |
| `npm run test:tools` | инструменты репозитория: установщики, синхронизатор плагинов, измерители, `check:drift`, эвал-каркас | поломан скрипт в `tools/` или `install-bundle/` |
| `npm run test:hooks` | хуки `dex-auto` (журнал, остановка, возобновление) | правка хуков |
| `npm run test:tracks` | оркестрация треков `dex-auto` на подменённых узлах | правка скриптов треков или узлов |
| `npm run test:mods` | чистая часть модов | правка мода |

`validate` и `npm test` дополняют друг друга и не заменяют `test:tools`, поэтому перед пушем всегда `precheck`. Точечно: `npm run validate:skills`, `validate:agents`, `validate:commands`, `validate:bundles`, `validate:node-contract`; один shell-тест: `bash tests/tools/<имя>.test.sh`.

### Проверка сайта документации

Если правка трогает `docs/guide/`, `site/` или данные каталога, добавляется сборка сайта с проверкой ссылок:

```bash
cd site
npm ci
npm run check      # типы страниц и конфига, заодно генерирует каталог
npm run build
npm run verify     # ссылки и ассеты под базовым путём, полнота каталога, индекс поиска
```

Проверка не ходит в сеть: внешние ссылки на GitHub и документацию Claude Code она не проверяет, поэтому якоря в них сверяйте сами.

### Проверка дрейфа

```bash
npm run check:drift
```

Ищет устаревшие ссылки и пути в нормах, расхождения чисел с `marketplace.json` и просроченные сверки с документацией. Находки a-c дают ненулевой код, просроченные сверки - сигнал (ошибка только с `--strict`). В CI не входит, запускайте локально, если трогали числа, ссылки на разделы или пути в нормативных текстах и в страницах этого сайта.

## Как тест на правило устроен

Каждое правило валидатора проверяется парой:

- на живом каталоге оно должно **молчать** (`validate`);
- на фикстуре `tools/__fixtures__/<валидатор>/<правило>/` с заведомым дефектом оно должно **сработать** (`npm test`).

Фикстура - оверлей поверх эталонного дерева `_base`, которое даёт ноль находок всеми валидаторами. Файл `expect.json` перечисляет ожидаемые побочные правила (`also`), подстроки сообщений (`messages`) и подстроки, которых быть не должно (`absent`). Набор сработавших правил должен точно совпасть с ожидаемым: неучтённое побочное правило считается ошибкой фикстуры, потому что маскирует поломку соседнего.

Добавляя правило, заведите три вещи: строку в [VALIDATOR_RULES.md](https://github.com/dex-it/ai-kit/blob/main/docs/VALIDATOR_RULES.md), фикстуру и (для нового валидатора) шаг в `package.json` и в CI.

## Слой 2: измерения, не блокирующие PR

| Команда | Что показывает |
|---|---|
| `npm run measure:context` | размер постоянного слоя, предзагрузки, групп skills и агентов (байты, строки, знаки; токены не оцениваются) |
| `npm run measure:listing` | бюджет листинга по описаниям, пары похожих описаний, листинг при установке бандла |
| `npm run metrics:propagation` | доля элементов каталога, до которых в среднем доходит правка одного (propagation cost) |
| `npm run metrics:run` | токены главного потока и узлов трека в сессии (телеметрия прогона) |

Сравнение до и после правки: `node tools/measure-context.js --json > before.json`, затем `node tools/measure-context.js --diff before.json after.json`. Правило нулевого прироста постоянного слоя поясняет, зачем: [Контекст: меньше, но невыводимое](/practices/context/).

## Слой 3: платные прогоны на модели

Валидатор судит форму файла, а не то, что исполнитель сделает на задаче. Для правок, где предмет - поведение, есть наборы с живыми прогонами. Они платные, не входят в CI и запускаются осознанно.

| Набор | Что проверяет | Когда нужен |
|---|---|---|
| `npm run test:activation` | поднимется ли skill на реалистичном запросе (`in-scope`) и не поднимется ли на соседнем (`near-miss`) | правка `description` skill |
| `npm run test:activation:agents` | под каким именем рантайм предлагает агента (видимость) | правка `name`, каталога, состава плагина-агента |
| `tests/trap-skills/` | ловит ли исполнитель ловушки skill без подсказки (метод «сжатие по свидетельству») | сокращение или усиление формы пункта |
| `tests/orchestration/`, `tests/node-contract/`, `tests/optimize-for-llm/`, `tests/norm-writing/` | поведение скиллов оркестрации, контракта, письма | правка тел этих skills |
| `tests/eval55/` | стенд замеров принципов написания на моделях Claude 5.5, с пред-регистрацией гипотез | решение «снять», «сократить» или «добавить» текст нормы |
| живой прогон сценария (`tests/_templates`) | маршрут целиком, от идеи до PR | крупные изменения конвейеров |

Правила платных прогонов: бюджет обязателен (`run` без `--budget` не стартует), серия привязана к одному коммиту, модель закреплена полным идентификатором, среда оператора изолирована. Метод и реестр прогонов - [tests/README.md](https://github.com/dex-it/ai-kit/blob/main/tests/README.md), стенд замеров - [tests/eval55/README.md](https://github.com/dex-it/ai-kit/blob/develop/tests/eval55/README.md).

Принцип чтения результата: малая серия не даёт вывода, а кейс, который проходят все условия на всех моделях, ничего не различает. Решение «снять правило» допустимо только для правил, у которых пройден контроль чувствительности. Подробнее: [Контекст: меньше, но невыводимое](/practices/context/).

## Что тестировать в какой правке

| Правка | Минимум | Дополнительно |
|---|---|---|
| skill: новая ловушка, описание | `validate:skills`, `precheck` | `test:activation` для описания; испытание в `tests/trap-skills/` для формы пункта |
| агент: фазы, frontmatter | `validate:agents`, `validate:node-contract`, `precheck` | `test:activation:agents` при смене имени |
| команда | `validate:commands`, `precheck` | живой вызов в тестовом проекте |
| бандл | `validate:bundles`, `install-bundle.sh <имя> --dry-run` | реальная установка в чистом профиле |
| мод | `typecheck:mods`, `test:mods`, `claude plugin validate --strict` | живой прогон `claude -p ... --plugin-dir` |
| скрипты `tools/`, `install-bundle/` | `test:tools` | |
| страницы сайта | сборка сайта и `verify` | `check:drift` |

## Перед PR

1. Тесты на закоммиченном дереве, а не на «грязном»: результат должен воспроизводиться на том, что уйдёт в PR.
2. `npm run precheck` зелёный.
3. Для сайта: `check`, `build`, `verify`.
4. В описании PR - что проверено и каким образом, а что сознательно не проверялось.
