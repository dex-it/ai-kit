Раздел для тех, кто хочет написать собственную единицу каталога: свой skill, агента, команду, мод или бандл. Страницы ведут по рабочему пути от идеи до PR и объясняют причину каждого правила. Нормы при этом не копируются: за точной формулировкой каждая страница ведёт в нормативный документ репозитория.

Раздел [Участие](/contributing/) описывает процесс (ветка, версии, Pull Request), здесь - сами единицы. [Архитектура](/architecture/) объясняет, как единицы связаны между собой.

## С чего начать: какой вид нужен

| Мне нужно, чтобы Claude... | Вид | Страница |
|---|---|---|
| знал неочевидные грабли технологии или правило процесса и применял их сам | skill | [Писать skill](/authoring/skill/) |
| выполнял роль с несколькими фазами, своим контекстом и проверяемым результатом | агент (специалист) | [Писать агента](/authoring/agent/) |
| запускался моим явным вызовом и вёл порядок шагов или оборачивал один CLI | команда | [Писать команду](/authoring/command/) |
| менял поведение или интерфейс самого Claude Code (панель, строка, перехват вызова) | мод | [Писать мод](/authoring/mod/) |
| ставился одной командой набором под роль | бандл | [Плагин и бандл](/authoring/plugin-bundle/) |
| получил доступ к внешней системе (трекер, база, браузер) | MCP-сервер или CLI-утилита | [MCP-конфигурации](/authoring/mcp/) |

Если сомневаетесь между видами, прочитайте [Skill, агент, команда, мод или MCP](/practices/choose-executor/): там разобран выбор на причинах, а не на ярлыках.

Короткий тест: «убрать упоминания моего проекта, и правило всё ещё читается» - это skill. «Нужны фазы и проверяемый результат» - агент. «Нужен вызов человеком с аргументом» - команда. «Нужно менять сам клиент» - мод.

## Общий путь любой единицы

1. **Проверьте, что единица нужна.** Измерьте, что модель без неё не справляется: skill или правило, которое модель и так знает, только занимает контекст. В каталоге есть такие случаи: несколько skills были сняты по результатам контрольных прогонов, потому что модель держала предмет без них (таблица снятых - в `install-bundle/README.md`).
2. **Выберите вид и имя** по [конвенциям](https://github.com/dex-it/ai-kit/blob/main/AGENTS.md#именование).
3. **Прочитайте фреймворк вида** (ссылки на каждой странице раздела).
4. **Напишите единицу** по странице вида, начиная с `description`: оно решает, выберут ли единицу.
5. **Проверьте валидатором точечно**, затем целиком: [Типичные ошибки валидаторов](/authoring/validators/).
6. **Внесите в каталог**: запись в `marketplace.json`, витрина README, версии, бандлы ([Плагин и бандл](/authoring/plugin-bundle/)).
7. **Прогоните гейт** `npm run precheck` и откройте PR: [Тестировать изменения](/authoring/testing/), [Pull Request](/contributing/pull-requests/).

## Принципы, общие для всех видов

Эти принципы повторяются в каждом фреймворке, и их полезно держать в голове до первой строки:

- **Цель и проверяемое «готово», а не процедура.** Claude знает, как собрать проект или найти файл. Текст сообщает, что должно получиться и по какому признаку это видно. Пошаговый скрипт дублирует знания модели и ломается при отклонениях.
- **Невыводимое.** В единицу попадает то, чего модель не выведет сама: ловушка, которую не заподозрит; договорённость; граница. Базовые знания и документация API туда не входят ([Контекст: меньше, но невыводимое](/practices/context/)).
- **Положительная форма с причиной.** «Делай X, потому что Y» исполняется надёжнее голого «не делай Z» ([Форма правил](/practices/rules-form/)).
- **Граница объёма.** Единица говорит, чего она не делает и когда останавливается; исход «менять нечего» законен ([Границы объёма и проверяемое «готово»](/practices/scope-done/)).
- **Один факт - один дом.** Не копируйте норму из соседа: сошлитесь.
- **Тексты пишутся для модели:** сухо, по делу, ASCII-пунктуация (дефис вместо длинного тире, `->` вместо стрелки, три точки вместо символа многоточия).

## Что нужно на машине

Node.js 22.6 или новее и `npm ci` в корне репозитория. Для модов - ещё Claude Code (для `claude plugin validate`), для shell-скриптов - `bash`. Рекомендуем работать в отдельном `git worktree`: проверки тяжёлые, а ветка PR должна оставаться чистой.
