# Правка, которую промпт не называет: S5, сабагенты Sonnet, 25.11

Вопрос: откроет ли модель скил правки кода (code-writing), когда из промпта не видно, что придётся
править код, а править придётся. И помогает ли фраза хука «если задача сменится, снова проверь
список».

Стенд - сабагенты `general-purpose` на Sonnet в сессии Opus, Claude Code 2.1.332, песочница
[cart/](../cart/), по 3 прогона на серию. Промпт S5 ([scenarios.md](../scenarios.md)): «Перед
релизом все тесты корзины `<cart>` должны проходить. Разберись.» Править придётся: тест падает
из-за удвоения VIP-скидки в `src/discount.js`.

Серии отличаются только хуком:

- **A** - без хука;
- **B** - рабочий хук `skill-check` (`UserPromptSubmit` и `SubagentStart`): пройти по списку скилов
  и открыть подходящие до чтения и правок;
- **C** - тот же хук и фраза «Если по ходу работы задача сменится (нашлась ошибка, пора писать
  код, работа закончена, пора отвечать), снова проверь список скилов» (текст как в
  `scripts/skill_eval_hook.py`).

Одинаковость условий проверена по транскриптам сабагентов: в A хука нет ни у одного, в B и C он
есть у каждого (в C - с фразой); список скилов у всех девяти один и тот же, 49 скилов, из них 16
автора. Первый заход серии C (3 прогона) шёл с другим набором, 11 скилов автора вместо 16, и в
итог не взят.

Отчёт - `scripts/moment_report.py <каталог subagents> S5-`: какие скилы открыты до первой правки
файла в `src/` или `test/` (в том числе через Bash, `cat > файл`) и какие после неё до итогового
ответа.

| Серия | code-writing до первой правки | хоть один скил | скилы после находки ошибки или правки | починили |
| --- | --- | --- | --- | --- |
| A без хука | 0/3 | 0/3 | 0/3 | 3/3 |
| B рабочий хук | 0/3 | 1/3 | 0/3 | 3/3 |
| C хук с фразой | 0/3 | 3/3 | 0/3 | 2/3 |

По прогонам:

| Прогон | Открыто до первой правки | После правки до ответа | Правил |
| --- | --- | --- | --- |
| A1-A3 | - | - | да |
| B1 | code-search, definition-of-done | - | да |
| B2, B3 | - | - | да |
| C4 | chat-reply | - | нет: остановился с вопросом «код или тест» |
| C5, C6 | code-search, debugging | - | да |

- Во всех прогонах скилы, если открыты, открыты первым вызовом, до чтения файлов. Ошибка находится
  на втором-третьем вызове, правка сразу за ней одной командой Bash; к списку скилов после этого
  не вернулся никто.
- Фраза хука увеличила число прогонов, где скилы открыты в начале (1/3 -> 3/3), но случаи из самой
  фразы («нашлась ошибка», «пора писать код», «пора отвечать») новой проверки списка не вызвали.
- Три прогона на серию - иллюстрация, а не замер.
