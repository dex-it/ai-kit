# Как проверяли, открывается ли скил

Открыт ли скил - только по транскрипту прогона: в нём есть вызов инструмента `Skill` с этим скилом.
Слова модели не считаются.

## Сабагенты

1. Сессия Claude Code с набором проверяемых скилов. Сабагент этой сессии видит тот же список
   скилов и инструмент `Skill` (проверено 17.11).
2. `scripts/prepare_runs.sh <каталог прогонов> S1-1 S1-2 ...` - копия песочницы `cart/` на каждый
   прогон. Каталог прогонов - во временной папке, не в репозитории.
3. Сабагент `general-purpose` на Sonnet, по одному на прогон, промпт из [scenarios.md](scenarios.md).
   Три прогона на сценарий.
4. `python3 scripts/run_report.py <каталог subagents сессии>` - какие скилы открыл каждый прогон.
   Каталог: `~/.claude/projects/<папка сессии>/<id сессии>/subagents`.

## Отдельная сессия `claude -p`

1. `scripts/run_series.sh <каталог прогонов> <каталог плагина со скилами> [модель]` - серия S1-S4
   по 3 прогона; один прогон - `scripts/run_headless.sh`. Скилы подключаются через `--plugin-dir`.
2. Хук для серии - `SETTINGS=scripts/hook-settings.json` (путь к `skill_eval_hook.py` в нём поправить
   под свой клон).
3. `python3 scripts/headless_report.py <каталог прогонов>` - какие скилы открыл каждый прогон.
4. Описания «что внутри + Активируется при» на русском и английском подменяет
   `scripts/descriptions_content.py`.

Результаты - в [results/](results/).

## Реальные сессии

`scripts/skill_load_rate.py` - сколько раз скил открыт из числа основных сессий за 30 дней, где он
был в списке доступных. `scripts/edit_vs_skill.py` - открывались ли скилы правки кода в сессиях,
где правили соответствующие файлы. Оба читают транскрипты `~/.claude/projects`.

## Оговорки

- Основная сессия на реальной работе - Opus, стенд - в основном Sonnet ради расхода токенов.
- У сабагента свой системный промпт, рабочая папка - репозиторий сессии со своим CLAUDE.md.
- Изменение описаний видно только в новой сессии: список скилов читается при старте.
