# Eval-протокол: доказать, что правка инструкции улучшила её, а не объявить

Операционализация шага «проверить эмпирически». Применять, когда правка затронула
`description`, когда шаг 7 дал `lost` хотя бы по одному пункту чеклиста, когда
две редакции надо сравнить по поведению исполнителя, либо когда правка меняет
процесс исполнителя (поиск, субагент, ожидание, объём отчёта): тогда ещё
[профиль прогона](#профиль-прогона-где-уходят-время-и-деньги). В прочих случаях шага 7
достаточно, и в отчёте это называется явно: «шаг 7 без расхождений, протокол не
применялся». Принцип: мерь дельту, не объявляй; рефлексия по конкретному провалу
важнее общих рассуждений «почему лучше».

## Что мерить

- **Токены/строки** до->после (рез без числа - не рез).
- **Re-derive чужими глазами.** Чеклист смыслов снят с оригинала до первой правки
  (шаг 2 скилла). Финальный текст целиком отдаётся субагенту - без оригинала, диффа и
  намерения правки; его ответы на вопросы чеклиста сличаются с чеклистом. Исход по
  каждому пункту: `derived`; `lost` - не воспроизводится либо воспроизводится в другом
  объёме или условии (правило стало шире, уже, мягче), правка откатывается; `dropped` -
  срезано намеренно, с основанием из «что резать». Пункт без исхода не проверен.
  `Agent` недоступен - сверка чтением финального файла целиком, в отчёте называется
  самопроверкой.
- **Валидатор по типу артефакта** (skill/agent/command): 0 error. Внесённая
  висячая/битая ссылка - дефект.
- **Триггеринг** (если правился `description`): см. триггер-проба ниже.

## Как мерить

- **Парный прогон.** Один вход, две версии инструкции (до/после); одна и та же
  модель-исполнитель на обе; метка версии скрыта от грейдера.
- **Грейдер по явным критериям.** Список проверяемых утверждений
  (`text`/`passed`/`evidence`) задаётся ДО прогона, не подгоняется под результат.
- **Слепое A/B.** Два выхода независимому судье без указания, какой новый; вердикт
  лучше/хуже/ничья по рубрике. Снимает смещение «новое значит лучше».
- **Триггер-проба (description).** ~20 запросов: должны сработать (in-scope) и не
  должны (near-miss - лексически близкие вне scope). Каждый прогнать несколько раз
  (активация шумит) -> доля срабатывания. Near-miss и парафразы держать ВНЕ набора,
  по которому крутишь формулировку: иначе подгонка под харнесс, не под охват.
  Отчёт диапазоном, не одним числом.
- **Worst-of-N и хрупкость.** Поведение модели чувствительно к мелочам формы
  (формат, порядок, разделитель). Прогони вход в нескольких семантически-равных
  формах, бери ХУДШИЙ результат, не средний. Переупорядочивание единиц - такая же
  поведение-меняющая правка, под тот же re-derive.
- **Downstream (следование инструкции).** Финальная проверка ценности:
  оптимизированный артефакт даёт у потребляющего агента более точное следование
  инструкции? Закодируй ограничения артефакта как верифицируемые (счётчик, формат,
  наличие секции/поля) и измерь долю соблюдённых до->после.

## Гейты

- **R-gate.** 0 пунктов `lost` в re-derive; 0 регресса на негативных
  (out-of-scope артефакт - отказ сохранён; near-miss не сработал). Нарушение -
  откат правки.
- **Якорь обязателен.** Самокритика привязана к внешней проверке
  (re-derive/проба/валидатор), не к мнению: непривязанная самооценка уводит в
  деградацию, а не в улучшение.
- Пороги заданы ДО прогона.

## Профиль прогона: где уходят время и деньги

Качество остаётся первым гейтом (re-derive, грейдер набора): профиль без качества
выбирает быстрые пустые прогоны. Профиль нужен, когда правка добавляет, снимает или
меняет шаг с поиском, субагентом, ожиданием, чтением больших файлов или объёмом
отчёта, либо исполнитель на пробе работал заметно дольше обычного.

**Источник данных - телеметрия самого Claude Code (OpenTelemetry), LangWatch для
профиля одного skill не нужен.** Снимается с прогона: токены (`input`,
`cache_creation`, `cache_read`, `output`) и стоимость по запросам, время запроса и
каждого инструмента, число ходов, вызовы инструментов с аргументами, субагенты (число,
длительность, токены).

```bash
node collector.mjs ./otel 4318    # приёмник (код ниже); наружу не ходит
export CLAUDE_CODE_ENABLE_TELEMETRY=1 CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1 \
  OTEL_LOGS_EXPORTER=otlp OTEL_TRACES_EXPORTER=otlp OTEL_METRICS_EXPORTER=otlp \
  OTEL_EXPORTER_OTLP_PROTOCOL=http/json OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318 \
  OTEL_LOGS_EXPORT_INTERVAL=1000 OTEL_RESOURCE_ATTRIBUTES=bench_run=<метка-прогона>
claude -p "<задание кейса>" --plugin-dir <плагин> --output-format stream-json --verbose
node summary.mjs ./otel <префикс-метки>
```

Флаги содержимого (`OTEL_LOG_USER_PROMPTS`, `OTEL_LOG_TOOL_DETAILS`,
`OTEL_LOG_TOOL_CONTENT`, `OTEL_LOG_RAW_API_BODIES`) не включаются: для времени и
стоимости они не нужны. Без `OTEL_LOG_TOOL_DETAILS` имя вызванного skill в событии
скрыто (`custom_skill`); имена берутся из потока `stream-json`. Метаданные несут
`user.email` и идентификаторы аккаунта: файлы телеметрии в репозиторий и отчёты не
идут.

```js
// collector.mjs: node collector.mjs <каталог> [порт]
import http from 'node:http'; import { appendFileSync, mkdirSync } from 'node:fs';
const [dir, port = 4318] = process.argv.slice(2); mkdirSync(dir, { recursive: true });
http.createServer((q, r) => { const b = []; q.on('data', c => b.push(c)); q.on('end', () => {
  appendFileSync(`${dir}/${q.url.split('/').pop()}.jsonl`, Buffer.concat(b) + '\n'); r.end('{}'); }); })
  .listen(+port, '127.0.0.1');
```

```js
// summary.mjs: node summary.mjs <каталог> [префикс метки]
import { readFileSync } from 'node:fs';
const [dir, pre = ''] = process.argv.slice(2), runs = {}, kv = a => Object.fromEntries((a ?? []).map(x => [x.key, Object.values(x.value)[0]]));
for (const l of readFileSync(`${dir}/logs.jsonl`, 'utf8').split('\n').filter(Boolean))
  for (const rl of JSON.parse(l).resourceLogs ?? [])
    for (const r of rl.scopeLogs.flatMap(s => s.logRecords)) {
      const at = { ...kv(rl.resource?.attributes), ...kv(r.attributes) };
      if (String(at.bench_run ?? '').startsWith(pre)) (runs[at.bench_run] ??= []).push(at); }
for (const [k, ev] of Object.entries(runs).sort()) {
  const is = n => e => String(e['event.name']).endsWith(n), req = ev.filter(is('api_request')), sum = f => req.reduce((a, e) => a + (+e[f] || 0), 0);
  const slow = ev.filter(is('tool_result')).filter(e => +e.duration_ms > 20000).map(e => `${e.tool_name}:${Math.round(e.duration_ms / 1000)}s`);
  console.log(k, 'запросов', req.length, 'USD', sum('cost_usd').toFixed(3), 'out', sum('output_tokens'), 'cache_w', sum('cache_creation_tokens'), 'cache_r', sum('cache_read_tokens'), 'мс', sum('duration_ms'), 'долгие', slow.join(',') || '-'); }
```

**Что искать в профиле:**

| Сигнал | Вероятная причина | Правка |
|---|---|---|
| инструмент дольше 20 с (`Bash` 120000 мс) | поиск без границы или ожидание | граница поиска в тексте (случай `find /` при нечитаемом доме) |
| один файл читается три раза и больше | шаг велит перечитывать целиком | читать один раз, держать результат |
| субагент в каждом прогоне, стоимость выше на половину | обязательный re-derive | оставить, пока он держит гейт качества; отменять только по парной серии |
| фоновый запуск и опрос (`ScheduleWakeup`) | ожидание вместо результата | на нашей серии не подтверждён (один прогон, на расширенной базе 0 из 4); править, только если сигнал повторился на серии: единичный прогон шум |
| `cache_creation` растёт на каждом запросе | контекст пересобирается | не менять порядок и состав подгружаемого между ходами |
| выходных токенов много | объём отчёта | форму отчёта сжимать, только если пункты отчёта не гейт |

**Как принять правку по профилю.** Парный прогон: одна модель, одни входы, не менее
пяти повторов на вариант на кейсе, где сигнал был. Порядок решения: грейдер набора
(качество не хуже) -> доля прогонов с сигналом упала -> время (среднее и максимум) и
стоимость не выросли. Малая выборка называется направлением, не размером эффекта; для
доли прогонов с сигналом считается точный тест Фишера на таблице 2x2. Правка, которая
снижает время ценой кейса (удаление «лишнего» примера дало время ниже и качество 0 из 5),
откатывается. Вход кейса должен быть полным (второй файл, дом рядом): неполный вход
даёт «провал», которого нет у skill. В отчёт идут версия, кейсы, повторы, среднее и
максимум времени, стоимость, доли.

**LangWatch - необязательный просмотрщик тех же данных.** Полезен, когда прогонов много
и нужны сквозные срезы (стоимость на PR и человека, сравнение недель), дерево вызовов и
реплей руками. Условия: только локальный экземпляр (`npx @langwatch/server`) с
`DISABLE_USAGE_STATS=1` и `LANGWATCH_CONNECT_DISABLED=1` (иначе сервер шлёт суточную
статистику на `app.langwatch.ai`); четыре флага содержимого выключены; облачный режим с
содержимым - только для проектов, код которых можно отдавать третьей стороне.
Подключение - по документации LangWatch (`langwatch instrument claude`). После работы
сервер останавливается, а его каталог данных (около 2 ГБ) удаляется.
