# Переиспользование: возможность правки против механизма проекта

Автор правки ищет до кода, ревью - после, по одним признакам.

Копия механизма - отложенный дефект: следующее изменение того же поведения, человеком или агентом, попадёт в
одну копию из нескольких, остальные разойдутся молча. Тесты копии зелёные, дифф чистый, поэтому поиск идёт и
вне правки.

## Возможности правки

Разложи правку на возможности - что её код делает независимо от предмета задачи: повтор при сбое, обход
страниц или курсора, опрос до состояния, кэш, валидация и нормализация входа, маппинг, форматирование,
пакетная запись, обработка и перевод ошибок, логирование, чтение конфигурации, регистрация в DI, маршруте,
очереди. Предмет задачи (счета, заказы) возможностью не является: двойник ищется по возможности, а слова
задачи его имени не содержат.

## Поиск двойника

Ищи по признаку кода, не по имени:

- **форма** - управляющая конструкция возможности: цикл с паузой и `catch`, цикл, пока есть курсор, условие
  на код ошибки, ключ кэша;
- **литералы** - коды статусов, коды сетевых ошибок, коэффициенты задержки, имена полей ответа;
- **общие каталоги** - `lib`, `common`, `shared`, `util`, `infrastructure` и их аналоги: прочитай перечень
  их экспортов целиком;
- **соседи того же рода** - другой клиент того же внешнего API, другой обработчик того же канала: чем они
  пользуются, тем должна пользоваться правка;
- **точки встройки** - DI-контейнер, маршрутизатор, конфигурация, конвейер ошибок и middleware, логгер:
  правка встраивается в них, а не обходит своим вызовом;
- **сама правка** - два её места, исполняющие одну возможность.

Охват - возможности, которые вводит правка, а не аудит репозитория. По каждой возможности итог - двойник
`file:line` либо «не найден» с тем, что искал (формы, литералы, каталоги).

## Исход по возможности

- **беру** - вызов механизма как есть;
- **адаптирую** - что меняется и где: различие только в форме данных закрывается адаптером на стороне
  правки; правка самого механизма допустима, пока его прежние потребители не меняют поведение и их тесты
  зелёные. Адаптация, меняющая контракт механизма для прежних потребителей, не делается в правке, а
  выносится тому, кто решает за задачу; до решения правка идёт исходом «пишу новое» с этой причиной;
- **пишу новое** - причина: двойника нет (что искал) либо он меняется по другой причине (раздел ниже).

Исход каждой возможности записывается туда, откуда его прочтёт ревью: план, описание правки, выход узла.

## Ложное обобщение

Два места сводятся в один механизм, только если меняются по одной причине. Проверка: назови изменение,
которое обязано попасть в оба места (код ошибки, ставший временным, новый формат курсора). Не называется -
сходство формы, а не дубль, и свести их значит связать правила, которые меняются порознь.

Пример: опрос готовности задачи и повтор при сбое оба - цикл с паузой, но условие продолжения, паузы и судьба
ошибки вызова у них разные: опрос ошибку вызова не повторяет, повтор только ради неё и существует. Сведение
одного к другому - дефект.

## Ревью

- **Находка** - место правки, двойник `file:line`, возможность, изменение из проверки выше (улика: без него
  находка не держится) и единый механизм, к которому свести, - взять как есть или адаптировать как. По
  определению это техдолг: следующее изменение потребует правки больше чем в одном месте. Причину писать
  новое, которую правка не назвала, ревью не додумывает: возможная причина идёт вторым исходом закрытия
  находки («либо причина названа в коде или плане»), тип и severity от неё не меняются.
- **Чисто** - только с трассой: перечень возможностей правки и по каждой, что искал. Голое «дублей нет» не
  засчитывается. Код проекта вне правки недоступен - исход «не проверено» с тем, что помешало, а не «чисто».
- **Неприменимо** - правка не вводит кода, исполняющего возможность: только данные, конфигурация, документы.
  Код тестов - код: его помощники и фикстуры судятся наравне.
- **Исход автора против кода** - «беру» или «адаптирую», которому код не последовал, и «пишу новое» без причины
  судятся той же находкой. Названная причина сверяется: «двойника нет» опровергает найденный двойник, «другая
  причина изменения» - проверка из «Ложного обобщения»; не выдержала - находка. Адаптация, вынесенная тому, кто
  решает, остаётся находкой со ссылкой на вынос.
- Предложение свести места, не прошедшее проверку из «Ложного обобщения», находкой не является.
