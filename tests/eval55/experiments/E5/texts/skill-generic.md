- **Skill = обобщённое правило, не конкретика одного проекта.** Читая критику конкретного MR, извлекать универсальный принцип. Сигналы необобщённости: имена Entity / классов / доменных терминов из реального проекта (`UpCore`, `MergeRequest`, `EyeLineData`, `ArchValue`); привязка к IDE-specific конвенциям (`.junie/`, `.cursorrules`) вместо обобщённого «любые документы проекта с конвенциями». Граница: имена API стека в стековом скилле допустимы, имена конкретного продукта - нет. Принцип проверки: «убери имена проекта - правило всё ещё читается и применяется?».
