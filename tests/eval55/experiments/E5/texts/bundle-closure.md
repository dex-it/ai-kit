- **Бандл должен быть замкнут по артефактам своих компонентов.** Каждый артефакт, который называет полной формой `` `dex-X:Y` `` агент, скилл или команда из состава бандла, обязан ехать в этом же бандле - установка плоская, каскада «специалист -> его скиллы» нет, недостающий артефакт не приедет и компонент молча деградирует. Это проверяет `npm run validate:bundles` (`bundle-not-closed`, `bundle-agent-not-closed`, `bundle-command-not-closed`). Триггеры: добавил компонент в bundle, добавил компоненту новую ссылку, создал артефакт для компонента из bundle. **Вызов, который называет артефакт как один вариант из набора, помечается `` `[справочно]` `` вплотную за вызовом** - меню стека перечисляет все стеки, а грузится один, по проекту: `` `dex-skill-kafka:kafka` `[справочно]` ``. Пометка снимает обязанность поставки и стоит у самого вызова, не у строки и не у заголовка - в одной строке соседствуют безусловный вызов и условные. Забыл пометку - валидатор потребует положить артефакт в бандл; поставил лишнюю - артефакт перестанет требоваться, и потребитель деградирует молча. **Пометка снимает поставку, поэтому ставится только там, где артефакт не нужен проекту вовсе** - чужой стек (`dex-skill-redis` в проекте без Redis), чужая зона (трек продукта у .NET-разработчика). Меню внутри собственного предмета пометки не несёт: «для DI - ..., для LINQ - ...» у .NET-кодера условно по задаче, а не по проекту - какой понадобится, решается в работе, и приехать обязаны все.
