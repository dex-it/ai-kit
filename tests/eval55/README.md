# eval55: стенд замеров на Claude 5.5

Стенд эпика [#7](https://github.com/dex-it/ai-kit/issues/7) (задача [#9](https://github.com/dex-it/ai-kit/issues/9)): принципы перевода каталога на Claude 5.5 - гипотезы про конкретные модели, и каждое решение «снять», «сократить» или «добавить» подтверждается здесь. Раннер один, эксперименты - модули в `experiments/`. Гипотезы, пороги и правила остановки - [PREREG.md](PREREG.md); запись фиксируется до платных серий.

Прогон платный и не входит в `npm test` и CI. Каркас без платных вызовов проверяет `tests/tools/eval55.test.sh` (`npm run test:tools`): `claude` подменён заглушкой.

E5: 10 нормативных текстов (3 исходных, 7 абзацев корневого `CLAUDE.md` на коммите пилота (теперь `AGENTS.md`)), у каждого 6-9 ограничений; `selfcheck` требует, чтобы исходный текст проходил все свои проверки. E10: 15 кейсов (база серии - `role`) на фикстурах `bug`, `clean`, `lib` (рядом файл с запахом, TODO, «заодно» правка, второй падающий тест, ложная посылка «бага нет», приманка в соглашении проекта, двусмысленная формулировка). Каждый кейс E1, E2, E10 проверен без прогона модели: нетронутая песочница не проходит проверку задачи (`node tests/eval55/run.mjs selftest` строит наборы и компилирует регулярки; офлайн-тест гоняет грейдеры против заглушек «чинит», «блуждает», «бездействует»).

**E1b** ([#50](https://github.com/dex-it/ai-kit/issues/50)): 10 задач сопровождения. Из списка #12 заменена задача «PR фичи сливается squash»: фраза «Ветки сливаются squash-ем» стоит в `tests/README.md` («Реестр прогонов»). Контрольные кейсы проверены без модели: нетронутая песочница не проходит ни одного (офлайн-тест), эталонная правка проходит все проверки (вручную, в офлайн-тест не вынесена).

## Запуск

```bash
node tests/eval55/run.mjs list
node tests/eval55/run.mjs selftest                       # наборы строятся, грейдеры известны, без вызовов
node tests/eval55/run.mjs plan all --reps 3              # ячейки и оценка стоимости, без вызовов
node tests/eval55/run.mjs plan stage1                    # ступень 1 (E3, E5, E10) или stage2 (E1, E2): Haiku и Sonnet, с калибровкой шума; Opus - только по --tiers
node tests/eval55/run.mjs hash                           # хэши входов стенда (для раздела «Заморозка» PREREG)
node tests/eval55/run.mjs plan E1b --reps 3                                         # E1b: 30 ячеек, 180 вызовов; зависимые задачи отдельно: --only-cases release-merge,release-tag,ref-repo-by-date,merge-settings
node tests/eval55/run.mjs run E1b --out ~/eval55/e1b --budget 20 --tiers haiku,sonnet --reps 3
node tests/eval55/run.mjs run E10 --out ~/eval55/e10 --budget 5 --tiers haiku,sonnet --reps 3
node tests/eval55/run.mjs baseline E10 --out ~/eval55/noise-e10 --budget 5 --tiers haiku,sonnet --reps 3   # две независимые базовые серии A и B на одном коммите + полоса шума
node tests/eval55/run.mjs report ~/eval55/e10 --band ~/eval55/noise-e10/A,~/eval55/noise-e10/B             # серия с полосой из пары баз
node tests/eval55/run.mjs report ~/eval55/base-A ~/eval55/base-B                                         # либо две копии базы внутри серий
```

Опции: `--conditions a,b`, `--cases N` (первые N кейсов; у E3 - число seed), `--only-cases a,b`, `--limit N` (первые N ячеек), `--effort` (по умолчанию `medium`), `--cell-cap USD` (потолок одного вызова, 2), `--parallel N` (2), `--commit REV` (коммит серии), `--keep` (оставить песочницы).

- **Коммит серии один.** `--commit` (по умолчанию `HEAD`) определяет всё, что берётся из репозитория: песочницу `repo`-ячеек (`git archive`), текст корневого `AGENTS.md` и набор условий E1 (разделы H2), E2 (строки правил), каталог skills и кейсы E7. Рабочее дерево не читается; полный хэш коммита и хэш входов стенда (`experiments/**`, `lib/**`, `priors.json`) пишутся в `meta.json`. Продолжение серии на другом коммите или после правки стенда отвергается, `report` предупреждает, если пара баз различается по коммиту или входам. Неизвестный `--commit` - ошибка.
- **Бюджет обязателен.** `run` без `--budget` не стартует; накопленный расход каталога сравнивается с ним перед каждой ячейкой, превышение останавливает серию с кодом 3. Расход берётся из `total_cost_usd` ответа.
- **Повторный запуск продолжает.** Ячейка - `эксперимент|условие|кейс|тир|повтор`; готовые пропускаются, поэтому прерванную серию можно запустить снова той же командой.
- **Каталог `--out` лежит вне репозитория** и не имеет `CLAUDE.md` и `AGENTS.md` среди предков: иначе память репозитория попала бы в песочницу. Раннер это проверяет.
- **Модель закреплена** полным идентификатором (`claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`) и сверяется с `modelUsage` ответа; расхождение - ошибка ячейки, не молчаливая подмена.

## Что записывается

Строка `results.jsonl` на ячейку: эксперимент, условие, кейс, тир, повтор, стоимость, ходы, токены, модели из ответа, проверки с исходом, доля пройденных, признак полного соблюдения, начало ответа. Рядом `meta.json`: версия `claude`, коммит репозитория, аргументы запуска, база эксперимента.

`report` печатает также таблицу «Проверки, на которых условия расходятся (по кейсу)»: для E2 это `rule-held:*` (нарушение правила), для E10 - выход за границу, для E1 - валидаторы.

Оценка ячейки - **доля пройденных проверок** (покомпонентное соблюдение) и **полное соблюдение** (все проверки). Это две метрики: в E3 они расходятся, и расхождение и есть предмет.

## Грейдеры

Детерминированные, без LLM-судьи: `output-matches`, `output-equals` и их отрицания, `file-exists`, `file-matches`, `file-not-matches`, `file-unchanged`, `file-changed`, `nothing-changed`, `only-changed`, `cmd` (код возврата команды в песочнице), `json-fields` (по проверке на поле JSON-ответа). Команды `cmd` берутся только из кода экспериментов репозитория, не из вывода модели. Судья-LLM допускается только вслепую и с перестановками, как в `docs/research/skill-form-vector-vs-solution/PREREG-blind.md`, и заводится протоколом конкретного эксперимента.

## Прокси и их границы

- **E7 - однократный выбор по листингу**, а не активация через `Skill` tool. Он дешёв и отделяет выбор от инфраструктуры, но не заменяет `tools/run-activation.js`, который меряет живую активацию.
- **E5 меряет выживание ключевых слов**, а не условий. Слово может пережить сжатие без своего условия, поэтому провал прокси однозначен, а успех - нет; решающий вывод по E5 требует слепого судьи.
- **Потолок.** Кейс, который проходят все условия на всех тирах, ничего не различает. Встроенный промт Claude Code уже держит объём, поэтому E10 без роли упирается в потолок даже на Haiku; условия `role` и `role-scope-line` добавляют давление роли, как в теле реального агента. Контроль чувствительности - в PREREG.
- **E2 и `.claude/rules/`.** Условие `without-rule` снимает одну строку корневого `AGENTS.md`; `.claude/rules/` и документы `docs/` остаются, и модель может найти норму там. Правило, которое дублируется в другом носителе, будет казаться менее нужным, чем есть.

## Полоса шума

Два независимых прогона одной базы (`baseline` кладёт их в `<out>/A` и `<out>/B`: условие-база эксперимента, один набор, один коммит, подряд, общий бюджет): на ячейку тира и условия берётся `max(|A - B|, 2 * SE разности)`, где SE разности средних - `sqrt(SE_A^2 + SE_B^2)` по ячейкам (кейс x повтор) каждой серии. Этот SE включает разброс между кейсами, поэтому полоса консервативна (шире парной). `report <A> <B>` и `report <серия> --band <A>,<B>` печатают полосу (nA, nB, средние, `|A - B|`, `2 SE`, полоса) и отмечают разности условий, вышедшие за порог `max(полоса, 2 SE пары)`. Правка принимается по решающим правилам PREREG, а не по ощущению от таблицы. Расчёт проверен офлайн на известных числах (`tests/tools/eval55.test.sh`).
