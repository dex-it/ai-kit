**Решения:**
- Поиск не дебаунсится: запрос уходит на каждое изменение, как сказано в задаче. Устаревшие ответы отбрасываются через флаг `ignore` в cleanup эффекта, поэтому медленный ответ на старую строку не перезапишет новый результат.
- Пробелы по краям обрезаются на клиенте, пустой запрос вызывает `getOrders()` без `q`. «У вас пока нет заказов» показывается только без запроса, при запросе без совпадений — «Ничего не найдено».
- Серверный API не менял: `GET /api/orders?q=` уже фильтрует, и я проверил это на реальном API с демо-данными (запросы «чай», «1003», «ЧАЙНИК», «кофе»).
