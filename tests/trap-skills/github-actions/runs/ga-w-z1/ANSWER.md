Оба workflow записаны. Ничего не запускал и не проверял: сети и сборки нет. Ничего не коммитил.

**Новые файлы**
- `.github/workflows/ci.yml`
- `.github/workflows/pr-size.yml`

**Что сделано**
- **Сборка и тесты (`ci.yml`):** запускаются на PR и на push в `main`, на .NET 8. Тесты `Contracts` идут на ubuntu и windows. Интеграционные тесты с Testcontainers идут только на ubuntu, потому что на windows-раннерах нет Linux-контейнеров.
- **Артефакты:** результаты тестов (trx) и покрытие (coverlet) сохраняются отдельным артефактом для каждой ОС.
- **Форматирование:** `dotnet format --verify-no-changes` с `continue-on-error`, отчёт загружается артефактом. Релиз не блокируется.
- **Лицензии:** вызывается reusable workflow `license-check.yml@v2` с `needs: test`.
- **Образ и деплой:** на `main` собирается образ, пушится в `registry.example.com/depot/api` с тегами `sha` и `latest` и логином из `REGISTRY_USER`/`REGISTRY_PASSWORD`. Затем `gh workflow run deploy.yml --repo dex/depot-infra`.
- **Метка размера (`pr-size.yml`):** метка `size/S`, `size/M` или `size/L` ставится по сумме `additions + deletions` из события. Порогов в задаче нет, я взял `<50`, `<300` и `≥300`.
- **Права:** в `ci.yml` у токена только `contents: read`.

**Замечания**
1. **Секрет для деплоя.** `GITHUB_TOKEN` не умеет запускать workflow в другом репозитории. Нужен секрет `DEPOT_INFRA_TOKEN` (PAT или токен GitHub App с `actions:write` на `dex/depot-infra`). Его надо завести, в задаче он не упомянут.
2. **Входы `deploy.yml`.** Я не знаю, какие входы он ждёт, и передаю его без параметров. Если нужен тег образа, добавьте `-f` с `github.sha`.
3. **Форки.** Сборка и тесты идут под `pull_request`, то есть без секретов и с токеном только на чтение. Метку ставит отдельный workflow на `pull_request_target`. Код PR он не выкачивает и не запускает, поэтому секретов форк не получит.
4. **Self-hosted раннеры `depot-linux`.** Не использовал. PR приходят из форков, и на раннере внутри сети компании мог бы выполниться чужой код. К тому же интеграционным тестам нужен Docker. Если захотите, их можно подключить только для push в `main` и для PR из этого же репозитория.
5. **Reusable workflow лицензий.** Для вызова нужно, чтобы репозиторий `ci-shared/.github` разрешал доступ из `dex`. Тег `v2` не закреплён по SHA.
6. **Тесты-заглушки.** Интеграционный тест в `StockTests.cs` сейчас заглушка и контейнер не поднимает. Тест пройдёт, но Postgres фактически не проверяется.
7. **Версия SDK.** `global.json` требует 8.0.100 с `latestFeature`, а Dockerfile использует 8.0.404. Расхождение безвредное, но заметное.
8. **Файл `docs/stage-values.md`.** В нём лежат значения для stage, и в workflow я их не использовал.
