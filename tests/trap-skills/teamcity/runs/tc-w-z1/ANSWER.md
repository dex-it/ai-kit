Конфигурацию TeamCity я написал, но ничего не собирал и не проверял: Maven, Kotlin и сервер недоступны. Ничего не закоммичено.

**Новые файлы**
- `.teamcity/settings.kts` задаёт проект `Depot` (сервер 2024.12) и создаёт для него `ServiceSpec`.
- `.teamcity/DotnetService.kt` — общая часть: класс `DotnetService(ServiceSpec)` строит всю цепочку. Для остальных девяти сервисов нужен свой `ServiceSpec` (имя, sln, VCS URL, образ).
- `.teamcity/pom.xml` — стандартный pom для Kotlin DSL, написан по памяти.

**Цепочка**
- Порядок: Build, затем Unit и Integration, затем Image с push, Deploy stage, Deploy prod. Все звенья связаны snapshot-зависимостями.
- Prod без триггера, запускается вручную. Stage стартует по VCS на `main`.
- Unit — это `Category=Contracts`, Integration — `Category=Integration`.
- Деплой берёт `deploy-values.yaml` из Image того же прогона цепочки (`sameChainOrLastFinished`). Образ в нём указан тегом и digest.
- Все конфигурации требуют Linux-агент с Docker.

**Защита от недавних происшествий**
- В каждой тестовой конфигурации билд падает, если запущено меньше одного теста.
- В каждой конфигурации билд падает, если в логе есть `System.OutOfMemoryException`, даже при нулевом коде `dotnet test`.

**Секреты**
- Параметры `db.password`, `registry.password` и `deploy.token` — hidden, значения в коде пустые, их надо задать в TeamCity.
- В скриптах они идут через `env.*`. Вход в реестр делается через `--password-stdin`.

**PR из форков**
- Они собираются отдельной конфигурацией «PR check (no secrets)»: только build и unit, без секретов. Integration, push и деплой идут только после слияния в `main`.
- Иначе код из форка мог бы забрать пароли.

**Замечания к задаче**
1. Не знаю, откуда `deploy-values.yaml` и как делается деплой. Файла в репозитории нет, формат нигде не описан. Я генерирую минимальный `image.repository/tag/digest` на шаге Image и деплою через `helm upgrade --install --atomic`. Чарт, namespace и пользователь реестра — заглушки с TODO, надо заменить.
2. URL репозитория и реестра в `ServiceSpec` — заглушки с TODO. Для PR-фичи использован GitHub-провайдер. Если хостинг другой, надо поправить.
3. Интеграционный тест сейчас пустышка: `Assert.Equal(OK, OK)`, а Testcontainers не поднимается. Условие «тестов ≥ 1» его пропустит, так что зелёный Integration пока ничего не доказывает. Пароль `db.password` передаётся как `DB_PASSWORD`, но тесты его не читают.
4. Кроме `.teamcity/pom.xml` для общего `.kt` рядом с `settings.kts` нужен Maven-проект. Для девяти сервисов `DotnetService.kt` лучше вынести в отдельный репозиторий или библиотеку, иначе его всё равно придётся копировать.
5. Версии Kotlin и плагинов приходят из родительского pom, и адрес `teamcity.example.com` там надо заменить на реальный.
6. `dotnet publish` выполняется внутри Dockerfile, отдельного шага для него нет.
7. На агентах для Image и деплоя нужен `helm`.
8. Сборки из форков идут на общих агентах с Docker. Если это недопустимо, для PR check нужен отдельный пул агентов.
