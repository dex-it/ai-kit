**Цепочка 1: вес с запятой (примеры 1 и 2)**
- Виджет шлёт `"weight":"1,5"` и `"2,3"`, строку без единицы с запятой.
- `parseWeight` (`src/parcel.js:174`) для такой строки делал `Number("1,5")`, получал `NaN` и возвращал `NaN` граммов.
- Проверка в `parseParcel` (`src/request.js:148`) была `NaN <= 0 || NaN > MAX`, то есть ложь, поэтому `NaN` проходил как корректный вес.
- `billableGrams(NaN)` давал `NaN`, `bandFor` не находил полосу (`NaN <= maxGrams` ложно), и `band.price` падал с `reading 'price'` (`quote.js:21`).
- Эту ветку добавили в SHIP-48 ради виджета, но десятичную запятую в ней не учли. Через сайт вес приходит числом, поэтому там ошибки нет.

**Цепочка 2: индекс с ведущим нулём (пример 3)**
- `zoneFor` (`src/zones.js`) приводил индекс к числу (SHIP-47, «для логов»): `"01067"` превращался в `1067`.
- `Math.floor(1067 / 1000)` даёт `1`, а в `zones.json` ключ региона — `"01"`, поэтому зона получалась `undefined`.
- `tariffs.zones[undefined]` возвращал `undefined`, и `tariff.bands` падал с `reading 'bands'` (`quote.js:20`).
- Затронуты индексы 01–09, то есть Саксония, Тюрингия и часть Бранденбурга. Остальные регионы не ломались.

**Фикс**
- `parcel.js`: единица измерения в регулярке стала необязательной, поэтому `"1,5"`, `"1.5"` и `"2"` разбираются одним путём как килограммы. Всё нечисловое (`"abc1"`, `"1,5,2"`, `undefined`, `NaN`) теперь даёт 400 вместо 500.
- `zones.js`: зона ищется по строке индекса (`code.slice(0, 2)`), числовое приведение убрано. Логирование региона в `shipments.js` не трогал, там своё `Number`.
