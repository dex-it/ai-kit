Я добавил `Jenkinsfile` в корень репозитория. Это единственный изменённый файл. Не коммитил и не запускал: сборок и сети нет, так что синтаксис и работу пайплайна не проверял.

**Что сделано**
- **Библиотека:** подключена `depot-pipeline-lib@v1.4.0`. Это стабильная метка, а не `main` и не `rc`. В `post { always }` вызывается `notifySlack(currentBuild.currentResult)`.
- **Агенты:** стадии идут на `dotnet-linux`. Глобального агента нет, поэтому ожидание подтверждения prod не занимает executor.
- **Workspace:** на постоянных нодах он чистится через `cleanWs()` в начале каждой стадии. Исходники передаются между стадиями через `stash`.
- **Тесты:** unit (`Category=Contracts`) и integration (`Category=Integration`) идут параллельно. Результаты trx публикуются через плагин MSTest.
- **Тег образа:** это наибольший тег `vX.Y.Z` по `sort -V`, а не по алфавиту, плюс номер сборки. Теги перед этим подтягиваются через `git fetch --tags`. Если подходящего тега нет, сборка падает.
- **Push и деплой:** выполняются только для `main`. Секреты берутся через `withCredentials` и не попадают в PR из форков. Токен деплоя передаётся как `--token "$DEPLOY_TOKEN"` в одинарных кавычках, поэтому подставляет его shell, а не Groovy. Логин в registry идёт через `--password-stdin` и отдельный `DOCKER_CONFIG`, который удаляется после push.
- **Подтверждение prod:** `input` стоит в стадии с `agent none` и таймаутом 3 дня. Общий таймаут сборки 4 дня, так что ответ лида на следующий день и позже не сорвёт сборку.

**Замечания к задаче**
1. **Push только для `main`.** В задаче не сказано, откуда пушить образ. Я пушу только с `main`, чтобы учётка `registry-creds` не попадала в сборки PR из форков. Если нужен push из feature-веток, это правится условием в `when`.
2. **Как `deploy.sh` узнаёт образ.** Скрипт принимает только `--token` и `--env`, а в репозитории его нет. Откуда он берёт тег образа, неясно. Сейчас `IMAGE_TAG` есть только в окружении стадий сборки. В стадии деплоя его нет, так что скрипту придётся определять тег самому, либо в вызов нужно добавить параметр.
3. **PR из форков и доверие.** Сборку PR из форков надо настроить в самом multibranch-job: политика доверия (Trusted contributors или Nobody) для Jenkinsfile из форка. Иначе автор форка может подменить `Jenkinsfile`. Это настройка job, в коде её нет.
4. **Плагины.** Нужны MSTest (шаг `mstest`), Pipeline: Input Step, Credentials Binding и Workspace Cleanup.
5. **`notifySlack` без агента.** Он вызывается в top-level `post` без ноды. Если шаг библиотеки требует workspace, его нужно обернуть в `node`.
6. **Pre-release теги.** Теги вида `v1.5.0-rc1` при выборе версии игнорируются. В задаче про них не сказано, это моё решение.
