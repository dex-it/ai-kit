# use-case-quality: сжатие по свидетельству, группа 3.1

Скилл `dex-skill-use-case-quality` 1.0.0 ([`inputs/SKILL-1.0.0.md`](inputs/SKILL-1.0.0.md)), эпик #291,
группа 3.1 (#300). Итог - 2.0.0: оракул из семи пунктов-названий и одной ловушки
([`inputs/SKILL-2.0.0.md`](inputs/SKILL-2.0.0.md)), строка в реестре [`tests/README.md`](../../README.md).
Принял пункт «Правило или число в шаге сценария» из снятого
[`use-cases`](../removed/use-cases/README.md) и его потребителя `usecase-analyst`.

Вход, среда, раннер, наборы прогонов и судьи - общие для группы, описаны в протоколе
[requirement-quality](../requirement-quality/README.md); прогоны и файлы вердикта лежат там же. Скилл
мерится кейсами w3 (сценарии из BRD) и r3 (ревью переработанных сценариев). Набор `v` по скиллу не
гонялся: первый черновик (`s`) прошёл, текст 2.0.0 = n1.

## Потребители

`use-case-writer` (самоконтроль, `self-check`), `usecase-analyst` (самоконтроль вместо снятого
`use-cases`), `requirements-reviewer` (оракул на сценариях и норма класса). Бандлы `product-manager`,
`system-analyst`. Кейса активации нет - оракул грузится по имени.

## Тип единиц (шаг 0)

14 H3-ловушек в четырёх разделах. Вводная (оракул ставит вердикт судья, автор - `self-check`) -
процедура, остаётся фразой.

## Открыто

- «Заголовок - действие интерфейса»: засева в w3 и r3 нет; ловушка держится как написана (на неё слита и
  одноимённая ловушка `use-cases`).
- «Смешение уровней цели»: w3-c1 записал валидацию суммы расширением UC-2002, со скиллом w3 чисто, но
  пункта в 2.0.0 нет - отличие могли дать соседние пункты (ветвление, вариации). r3 засев формата
  карты оба набора судят противоречием ADR-001, то есть засев смешан с вне-скилловым дефектом.
- Вне скилла: «нет ответа» провайдера - со скиллом ветка с терминалом; лимит ниже израсходованного -
  w3-c1 досочинил исход (норма `usecase-analyst`, не оракула).
