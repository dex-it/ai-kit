`POST /api/orders/:id/pay` готов и подключён в `server.ts` вместо заглушки. `npm run typecheck` проходит без ошибок. В `npm test` у api прошло 17 тестов, у web 2. Вывод e2e я не смотрел. Playwright-тесты не запускал, браузеры не установлены.

Изменённые файлы:
- `api/src/app.ts` — эндпоинт оплаты.
- `api/src/payments/http-gateway.ts` — новый, HTTP-реализация `PaymentGateway`.
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`.
- `api/src/domain/order.ts` — необязательное поле `transactionId`.
- `api/src/server.ts` — подключена HTTP-реализация шлюза.
- `api/test/orders.test.ts` — тесты оплаты: успех, отказ банка, чужой заказ, повторная оплата, сбой письма.
- `api/test/http-gateway.test.ts` — новый, тесты клиента шлюза.

Решения:
- **Повторы при сбоях шлюза:** сетевой сбой, `409` и `5xx` клиент повторяет до 3 раз с тем же `order_id`, как описано в контракте (повтор возвращает результат первого списания). Если результат так и не получен, API отвечает `502 payment_unavailable`, статус заказа не меняется. Таймаут запроса 10 секунд. Значения по умолчанию для `PAYMENT_URL` (`http://localhost:4040`) и `PAYMENT_API_KEY` (пустая строка) выбрал я.
- **Письмо и аналитика:** ошибки `notifier.orderPaid` и `analytics.track` после успешного списания только логируются и не ломают ответ `200`.
- **Отмена во время списания:** после ответа шлюза статус заказа проверяется ещё раз. Если заказ за это время отменили, отвечаем `409` и пишем в лог ошибку про одобренное списание, потому что деньги уже списаны.
- **Падение при ошибке:** обработчик обёрнут в `try/catch` с `next(err)`, потому что в Express 4 отклонённый промис не попадает в `errorHandler`.
