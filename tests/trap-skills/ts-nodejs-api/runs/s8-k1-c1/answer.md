`POST /api/orders/:id/pay` готов. `npm run typecheck` проходит без ошибок. `npm test` проходит: 13 тестов в api и 2 в web. Новые тесты на оплату входят в эти 13. Playwright не запускал, браузеров нет.

Изменённые файлы:
- `api/src/app.ts` — эндпоинт оплаты
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`
- `api/src/domain/order.ts` — поле `transactionId`
- `api/src/server.ts` — вместо заглушки подключён HTTP-шлюз
- `api/src/payments/http-gateway.ts` — новый файл, HTTP-реализация шлюза
- `api/test/payment.test.ts` — новый файл с тестами

Тесты закрывают успешную оплату, отказ банка (`402`), чужой и несуществующий заказ (`404`), повторную оплату (`409`) и запрос без авторизации (`401`). Ещё один тест проверяет, что сбой уведомления не ломает ответ.

**Решения:**
- **Повторы:** шлюз идемпотентен по `order_id`, поэтому клиент до трёх раз повторяет запрос при сетевых сбоях, таймауте, `409` и `5xx`. Если результат так и не подтвердился, API отвечает `502 payment_unavailable`, а заказ остаётся `new`.
- **Письмо и аналитика:** после успешного списания их сбои только логируются, ответ всё равно `200`, потому что деньги уже списаны. Статус заказа перепроверяется после ответа шлюза, на случай параллельной отмены или оплаты.
- **Значения по умолчанию:** `PAYMENT_URL` по умолчанию `http://localhost:4040`, `PAYMENT_API_KEY` по умолчанию пустой. Это значения по аналогии с остальными сервисами в `config.ts`, при необходимости поменяйте.
