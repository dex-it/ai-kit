`POST /api/orders/:id/pay` готов: в `api` проходят `npm run typecheck` и `npm test` (14 тестов). Запуск сервера с реальными переменными и реальный шлюз не проверялись.

**Изменённые файлы** (в `api/`):
- `src/payments/http-gateway.ts` (новый)
- `src/app.ts`
- `src/config.ts`
- `src/server.ts`
- `src/domain/order.ts`
- `test/pay.test.ts` (новый)

**Решения:**
- **Переменные окружения:** `PAYMENT_URL` и `PAYMENT_API_KEY` проверяются в `config.ts` при импорте, как требует практика команды. Без них сервис падает при старте, а не при первой оплате. Из-за этого для запуска сервера теперь нужны обе переменные.
- **Шлюз:** `HttpPaymentGateway` повторяет запрос до 3 раз при сетевом сбое, таймауте (10 с), `409` и `5xx`. Повтор идёт с тем же `order_id`, а шлюз по нему не списывает второй раз. Если попытки закончились, ответ `502 payment_unavailable`, статус заказа остаётся `new`.
- **Побочные эффекты после оплаты:**
  - Ошибки письма и аналитики только логируются и не ломают ответ `200`.
  - Параллельный второй запрос на тот же заказ получает `409`, пока идёт первый.
  - В заказ добавлено необязательное поле `transactionId`.
- **Тесты:** на эндпоинт (успех, отказ `402`, чужой и несуществующий заказ `404`, повторная оплата `409`, сбой письма) и на шлюз (повтор после сетевого сбоя, отказ банка).

В `app.ts` обработчик оплаты обёрнут в `try/catch` с `next(err)`: Express 4 не ловит ошибки из async-обработчиков. Prettier запустить не удалось, нужна сеть, поэтому отступы в `app.ts` поправлены вручную.
