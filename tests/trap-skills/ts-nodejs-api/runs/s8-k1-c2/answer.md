`POST /api/orders/:id/pay` готов, и `npm run typecheck` и `npm test` проходят (16 тестов в api, 2 в web).

**Что изменено**
- `api/src/app.ts` — эндпоинт `/pay`.
- `api/src/payments/http-gateway.ts` (новый) — HTTP-реализация `PaymentGateway`.
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`.
- `api/src/server.ts` — вместо заглушки подключён `HttpPaymentGateway`. Если переменные не заданы, остаётся заглушка, которая бросает ошибку.
- `api/src/domain/order.ts` — у заказа добавлено необязательное поле `transactionId`.
- `api/test/orders.test.ts` — тесты оплаты: успех, отказ, чужой и несуществующий заказ, оплаченный заказ, сбой письма после оплаты.
- `api/test/http-gateway.test.ts` (новый) — тесты клиента шлюза.

**Решения**
- Клиент шлюза повторяет запрос до 3 раз с тем же `order_id`, если был сетевой сбой, таймаут, ответ `5xx` или `409`. Шлюз по контракту не спишет повторно. Если попытки кончились, эндпоинт отвечает `502 payment_unavailable`, а заказ остаётся `new`.
- Сбой письма или аналитики после списания только пишется в лог и не ломает ответ `200`: деньги уже списаны.
- Для заказа, который сейчас оплачивается, повторный запрос получает `409`. Эта защита хранится в памяти процесса, так что на нескольких инстансах она не сработает. Там спасает только идемпотентность шлюза.

В `app.ts` код внутри `try` в обработчике `/pay` остался без отступа. Я пытался запустить `prettier`, но сеть для него закрыта, поэтому форматирование не поправил.
