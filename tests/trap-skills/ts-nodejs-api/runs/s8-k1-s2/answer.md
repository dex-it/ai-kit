Оплата заказа готова: `POST /api/orders/:id/pay` работает. `npm run typecheck` проходит, в `npm test` зелёные все 11 тестов api и 2 других. Prettier не запустился (нет сети), поэтому `src/app.ts` не отформатирован автоматически.

**Изменённые файлы** (все в `api/`):
- `src/payments/http-gateway.ts` (новый)
- `src/app.ts`
- `src/config.ts`
- `src/server.ts`
- `src/domain/order.ts`
- `test/orders.test.ts`

**Решения:**
- **Переменные окружения:** `PAYMENT_URL` и `PAYMENT_API_KEY` проверяются в `config.ts` при импорте, как требует практика команды. Без них сервис падает на старте, а не на первой оплате. Теперь их нужно задавать при каждом запуске api.
- **Шлюз:** `HttpPaymentGateway` делает до 3 попыток с таймаутом и backoff при сетевых сбоях, `5xx` и `409`. Шлюз идемпотентен по `order_id`, поэтому повтор не спишет деньги второй раз. Если результат так и не получен, ответ `502 payment_unavailable`, а заказ остаётся в статусе `new`.
- **Эндпоинт:** повторный параллельный запрос на оплату того же заказа получает `409`, пока первый в работе. Письмо и событие `order_paid` отправляются после сохранения оплаты, и их сбой только логируется, а ответ остаётся `200`.
- **Тесты:** в `test/orders.test.ts` добавлены четыре сценария: успешная оплата, отказ банка (`402`), чужой заказ (`404`) и повторная оплата (`409`).
