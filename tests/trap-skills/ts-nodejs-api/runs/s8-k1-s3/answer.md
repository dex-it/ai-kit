`POST /api/orders/:id/pay` готов. `npm run typecheck` и `npm test` зелёные: в api 16 тестов, в web 2. Запрос к реальному шлюзу или песочнице не делал (внешней сети нет).

Изменённые файлы:
- `api/src/app.ts` — эндпоинт оплаты.
- `api/src/config.ts` — `PAYMENT_URL` и `PAYMENT_API_KEY`.
- `api/src/domain/order.ts` — необязательное поле `transactionId`.
- `api/src/server.ts` — вместо заглушки подключён `HttpPaymentGateway`.
- `api/src/payments/http-gateway.ts` — новый, HTTP-реализация шлюза.
- `api/test/pay.test.ts` — новый, тесты на эндпоинт.
- `api/test/http-gateway.test.ts` — новый, тесты на шлюз.

- **Переменные окружения:** `PAYMENT_URL` и `PAYMENT_API_KEY` проверяются при старте сервиса. Если их нет, сервис не запустится с понятной ошибкой, а не упадёт на первой оплате. Теперь их нужно задавать везде, где запускается `server.ts`.
- **Повторы запроса к шлюзу:** при сетевом сбое, таймауте, `409` и `5xx` шлюз вызывается повторно, всего 3 попытки. Шлюз не спишет деньги дважды, потому что ключ идемпотентности — `order_id`. Ответ `401` и `400` не повторяются.
- **Ответы эндпоинта:** кроме заказа в статусе `new` и отказа банка, на `409` отвечает и параллельная оплата того же заказа. Если письмо или аналитика упали уже после списания, ответ всё равно `200`, ошибка пишется в лог.

Если шлюз остаётся недоступен после трёх попыток, эндпоинт отвечает `500`, заказ остаётся `new`. Результат списания при этом неизвестен: повторная оплата того же заказа вернёт результат первого списания.
