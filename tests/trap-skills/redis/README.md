# redis: сжатие по свидетельству, группа 4.3

Скилл `dex-skill-redis` 1.1.1 ([`inputs/SKILL-1.1.1.md`](inputs/SKILL-1.1.1.md)), эпик #291, группа 4.3 (#304). Итог - 1.2.0
([`inputs/SKILL-1.2.0.md`](inputs/SKILL-1.2.0.md)): три названия из 12 ловушек и чек-листа (старт без Redis, потеря
распределённого лока, лимит запросов на границе окон); C1, C3, C5-C8, C10, C11 сняты контролем, C4 - дубль, дом
`dotnet-resilience`. Заход, мини-проект, среда, наборы, расход, дефекты кейсов и шаг 0 - в протоколе группы
[kafka](../kafka/README.md#заход-группы-43); здесь - вердикт скилла. Таблицы судьи - [`judge/`](judge/).

## Потребители

`redis-specialist` (Phase 2, Skill tool, sonnet), `dotnet-performance-analyst` (`[справочно]`, если Redis в стеке),
`discover-reviewer` (`[справочно]`); бандлы `dotnet-fullstack`, `infrastructure`, `cli-tools` (утилита `redis-cli` - не
скилл). Узлы dex-auto и P98 не вызывали. Кейсы активации `redis-in`, `redis-near`.

## Шаг 0

Stampede (C4) = `dotnet-caching` H1 (дом - пункт `dotnet-resilience`), fixed window (C12) - дом `redis` по записи
`reference-architectures`, остальные дубли - [таблица группы](../kafka/README.md#шаг-0). Кейсы: G-C (код, `docs/tasks/FUL-13.md`: кэш цен,
лок пересчёта, лимит 100 в минуту, корзина, очередь писем, StackExchange.Redis 3.4.5), RV-C (ревью `catalog-cache`: C1-C12,
приманки P1 короткий TTL флага «в обработке» и P2 префикс версии `v2:cart:`, вне скилла O1 `Math.Round` цены в кэше, O2 ключ API
в логе). Дефект кейса G-C: ADR-0001 задаёт RabbitMQ для команд, поэтому оба прогона делали очередь писем на MassTransit -
клетка C11 в коде `n/a`, судится ревью.

## Итоговая редакция на всех кейсах

1.2.0 (три названия) - выше; N-G, N-RV с пятью редакциями - в [протоколе группы](../kafka/README.md#итоговая-редакция-на-всех-кейсах):
приманки Redis P1, P2 - 1 во всех шести прогонах. Активация: `redis-in` 3/3, `redis-near` 3/3.

## Открыто

- **C4:** контроль в ревью 0/2 при том, что дом - `dotnet-resilience` (там ревью ловило ложный комментарий о single-flight);
  в `redis` не возвращается по шагу 0 - вопрос владельцу о доме для распределённого случая.
- **C9, G-C:** `c2` без fencing-токена принят как допустимое решение (продление с проверкой владения и требование
  идемпотентности порта); Redlock в одноузловом compose нереализуем и не требуется.
- **C12:** решение (скользящее окно, token bucket, GCRA) выводит исполнитель, в пункте только название.
- Рантайм (потеря лока при failover, поведение клиента при недоступном Redis) не наблюдался.
