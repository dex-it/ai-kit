## Шаг 0 и проход «нужен ли скилл»

- **Потребитель один** - справка `dotnet-runtime-diagnostician` («Статика-дополнения (не Skill-load)»), не загрузка; бандл `runtime-diagnostics` включал скилл. Маршрута к скиллу у агентов нет.
- **Дубли:** retry без idempotency ~ `distributed-resilience` (снята, R-d 5/5); `Cancellation не пробрасывается` ~ `dotnet-async-patterns` A6 (сводит к `CancellationToken`, снята). Двойник
  наследует вердикт дома.
- **Решение:** кейс-контроль DA1/DA0 до снятия; провал контроля - единицы переносятся в ось агента, не доказанное на прогоне - `unverifiable`.

## Вердикт

A6 вернулась названием в ось агента: «время приложения, записанное в БД и сравниваемое с `now()` БД» (справочная строка вместо `dex-skill-deep-audit`). Носитель прогона - файл-редакция оси
(прецедент `ts-patterns` группы 2.3): набор `a`, DA1 `a1`, `a2`: A6 2/2 (обе находки называют `DateTime.UtcNow` против `now()` БД и дрейф часов); DA0 `a1`, `a2`: ложных находок по оси нет (оба
прогона явно пишут, что все времена берутся из БД).

## Открыто

- **Ось агента не мерилась как поручение агента** (`dotnet-runtime-diagnostician` исполняет фазы с живым процессом); носитель - файл-редакция оси.
- **A6 в контроле 1/2** при n=2; добор до 5 по правилу эпика не делался (единица ушла в ось).
- **Критерий DA0** сужен до предмета скилла (как OBS0, R0A2 группы 4.1); строгий «ни одной Critical/Medium» недостижим для реалистичного компонента, второй оценщик это показал.
- **Альтернатива владельцу:** оставить скилл с одним названием A6 (как `dotnet-async-patterns`). Выбрана ось агента, потому что единственный потребитель - агент.
