## Неточности текста

- «Обычный KFold для классификации: фолды без одного класса» - `cross_val_score(cv=5)` у классификатора берёт `StratifiedKFold` сам (проверено на scikit-learn 1.9.1); контроль приманку CB1 не поднял ни разу.
- «Предобработка вне `Pipeline` - утечка» держится, но `TargetEncoder.fit_transform` в sklearn 1.9 делает внутреннюю кросс-подгонку; утечка остаётся через обучение на всех данных до разбиения, контроль её поднял 2/2.
- «StandardScaler для деревьев - вред» - лишний шаг без вреда; контроль писал minor (приманка CB2).

## Дубли (шаг 0)

DDP (`python-pytorch` = `python-ml-optimization`), `no_grad` (тот же двойник), AMP (`python-pytorch`, `python-tensorflow`, `python-ml-optimization`) и GridSearch (`python-ml-optimization`; в `python-classical-ml` единицы нет, есть только слово в `description`) решены до кейсов: единица мерится в одном кейсе, двойник наследует вердикт. Все DDP-, `no_grad`- и AMP-единицы сняты контролем 2/2 (RV-PT, RV-DDP, RV-TF), GridSearch снят (RV-OPT). Заморозка backbone: V8 (`python-computer-vision`) и N8 (`python-nlp-transformers`) сняты контролем 2/2, поэтому противоречие без условия исчезло вместе с пунктами.

## Открыто

- C9 в K-ML: `c2` осознанно не взвесил классы (допустимо по существу при ранжирующей метрике, ключ судит буквально) - вопрос владельцу.
- C10 в K-ML: ключ требует ранней остановки; фиксированные 300 деревьев - допустимое решение по существу, единица держится буквой ключа.
- Реальные `accounts.parquet` не гонялись: утечка по времени (C5, C7) проверена на коде и синтетических данных тестов исполнителя.
- Решение 2 эпика (число прогонов) не принято: контроль по 2 прогона, возможны ложные снятия; перепрогон - при его принятии.
- Рез `optimize-for-llm`: у исполнителя нет `Skill`, `dex-skill-optimize-for-llm:optimize-for-llm` не вызывался - `unverifiable`; редакция в десять строк, резать нечего.
