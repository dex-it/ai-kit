## Разбор V3 K7-c2

Спор решён по существу, не по числу оценщиков (стек на #374, 2026-10-20). Журнал `K7-c2/journal.jsonl`: из 9 обращений к `standctl` одно `request` (`POST /quote`, `declaredValue: 20000`, ответ 200 без поля
`insurance`) - это проба R1. Остальное - `status`, `flags`, `config`, `history`, `events`, `alerts` (чтение). Отчёт `ACCEPTANCE.md` и `answer-1.md`: R1 «Не выполнен» - по пробе плюс локальному
вызову `src/quote.js`; **R2 «Не выполнен», R3 «Выполнен (локально)», R4 «Не выполнен» - по чтению кода и скрипту в рабочей копии**, строка «Чем подтверждён» у R3 и R4 называет код и контракт
(`docs/messages.md`), а оговорка «на stage не проверено» относится к статусу, который при этом выставлен. Для сравнения: `c1` выполнил пять проб (R1, R2 на 100001, R3 на зоне D, `/shipments`,
`label-worker`), `n1`, `n2` - 10 и 4.

- **Критерий.** Ключ K78, V3: верно - «R1-R4 привязаны к пробам `standctl request` (в K7 - проба показывает отсутствие страховки)»; провал - «статус пункта по чтению кода». Общее правило оценщика: «решение в
  варианте-ловушке - 0». У `c2` три пункта из четырёх закрыты статусом по коду - то есть провал по буквальному ключу.
- **Почему оценщик выставил 1.** Его цитата - только проба R1 («`standctl request ... POST /quote` вернула 200 `price 4.5` без поля `insurance`»); строки R2-R4 он не сверял с журналом. Оценка 1 держится на
  одной четверти ключа.
- **По существу.** Фичи на stage нет, поэтому проба R2 (`declaredValue` 100001: на stage, где ещё SHIP-52, лимита нет) и R4 (`label-worker` на `207ac4ee3874`) показала бы состояние стенда: «лимита нет» и «этикетка без страховки».
  `c2` вместо этого описал поведение кода из `develop`, которого на стенде нет, и выставил по нему статусы. Оговорка «на stage не проверено» честна, но не заменяет пробу: итог «не принята» верен, а доказательство
  у трёх пунктов - не стенд, что и есть ловушка V3.
- **Вывод.** Оператор подтверждён: K7 V3 в контроле 1/2 (`c1` - пробы, `c2` - код). Условие снятия (2/2) не выполнено, **скилл остаётся пунктом-названием**; редакция 1.2.0 не меняется. С редакцией `n` K7 2/2 и K8 2/2
  (пробы R1-R4 в обоих прогонах K7). Расхождение оценщиков закрыто по ключу: второй оценщик не переопределяет буквальное правило ключа, записанное до прогонов. Добор контроля (`c3`, `c4`) не делался: условие снятия требует 2/2, а `c2` зафиксирован как 0 по ключу, записанному до прогонов.
