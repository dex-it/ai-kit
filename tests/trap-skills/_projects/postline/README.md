# Мини-проект Postline: вход наборов группы 4.1

Платформа авторов (публикации, лента, донаты, поиск, уведомления, эфиры, аналитика) - документы с числами
нагрузки, ADR, дизайн и планы, немного кода модуля уведомлений. Сборки нет. Вход наборов
[cap-consistency](../../cap-consistency/README.md), [scalability](../../scalability/README.md),
[capacity-planning](../../capacity-planning/README.md), [reference-architectures](../../reference-architectures/README.md),
[tech-evaluation](../../tech-evaluation/README.md), [adr-quality](../../adr-quality/README.md),
[design-quality](../../design-quality/README.md), [plan-quality](../../plan-quality/README.md) (эпик #291, #302).
Файл - ключ для судьи, исполнителю не подаётся: `setup.sh` копирует в каталог прогона только `stages/` и `branches/`.

```
setup.sh <dest> [ветка]   git-репозиторий: stages/* - коммиты main, branches/<имя>/* - ветка feature/<имя> от main
stages/1-base             docs/system.md (нагрузка, ёмкость, команды, редакции), ADR-0001..0004, журнал решений,
                          выдержка PushGate, дизайн PL-05 (ссылки на пункты ADR-0004), src/notifications
stages/2-adr-0002-review  правка ревьюера в ADR-0002 (п.5) от 2026-09-28 - после снятия черновика PL-25
run-group-4-1.sh          раннер: промпты дословно, флаги исполнителя, выход в runs/ протокола скилла-дома
judge-blind.sh            второй оценщик вслепую: ключ кейса + выход, без сведений о наборе
key/<кейс>.md             ключ кейса - то, что получает второй оценщик (копия строк этого файла)
```

## Засчитывание

Записано до первого прогона; правка после прогона - явной записью ниже, в пользу снятия не засчитывается.

- **K (единица скилла).** Автор (D, C, T, P): в документе стоит решение из перечня допустимых в месте, где решается
  ситуация, либо вариант-ловушка явно отвергнут с причиной. Молчание при ситуации, заданной входом, - провал;
  решение в варианте-ловушке - провал. Слово ловушки не требуется. Порог-эвристика скилла судится по исходу.
  Ревью (R): находка указывает на засеянное место или называет ситуацию в нём, и её исход (правка, риск) снимает
  дефект; severity не важна. ADR-автор (W): по диффу - что стало с файлами.
- **P (приманка).** Автор: провал, если документ принимает решение, которое приманка делает ложным (названо в
  строке). Ревью: провал, если находка по приманке требует правки с severity blocker или major.
- **O (вне группы).** Засчитан, если дефект найден (ревью) или требование выполнено (автор): по нему видно сужение охвата.
- **Кейсы «ничего не менять»** (R0A, R0P): засчитан, если ни одной находки blocker/major; minor допустим. D6 - по
  своим клеткам.
- **Пограничное.** Ссылка «см. ADR / см. спецификацию» на существующий в репозитории файл - не дыра. Вариант
  «уточнить у владельца» без решения на время ожидания - молчание. Находка ревью, называющая дефект другим
  словом (например, «устареет» вместо «смешение нормы и состояния»), засчитывается, если указывает на то же место
  и та же правка его снимает.
- **Вердикт.** Первичный - оператор по выходу (судьи-субагенты оператора с этим ключом; каждый провал и каждое
  расхождение с вторым оценщиком проверяются оператором по месту). Второй оценщик вслепую - `judge-blind.sh`
  (`claude-opus-5-5`, effort medium, без инструментов) - судит заранее выбранные прогоны: все с индексом 2
  контроля (`c2`) и итоговой редакции (`f2`). Расхождения - строкой в протокол.
