# Мини-проект Loyalty: вход группы 3.2

Корпус требований программы лояльности с `decision-log`, счётчиком номеров и утраченным журналом,
плюс второй репозиторий (Wallet) с чужой раскладкой требований. Вход наборов
[decision-log](../../decision-log/README.md), [unit-identity](../../unit-identity/README.md) и
[artifact-naming](../../artifact-naming/README.md) (эпик #291, группа 3.2, #301). Файл - ключ для
судьи, исполнителю не подаётся: `setup.sh` копирует в каталог прогона только `stages/`.

```
setup.sh <dest> [corpus|alien]   git-репозиторий: corpus - Loyalty, alien - Wallet; stages/* - коммиты main
run-group-3-2.sh <case> <set> <idx> [skill-file...]   прогон кейса, выход - decision-log/runs/<case>-<set><idx>/
```

Раннер: `claude -p`, `claude-sonnet-5-5`, effort medium, без MCP (`--strict-mcp-config`), без `Skill`
tool, из команд - только git. Прогон со скиллом подаёт копии `SKILL.md` путём. Выход прогона -
`DIFF.patch` рабочего дерева и `ANSWER.md` - финальный ответ исполнителя.

## Корпус Loyalty (`corpus`)

Соглашения корпуса видны из файлов, исполнителю их никто не называет:

- `.docs_layout` - `root`, `counter`;
- `.req_counter/` - файл на ключ: `feature` = 03, `NN.<КЛАСС>` - последний номер класса в блоке;
- папка фичи `<NN>-<слаг>`, в ней `brd.md`, `srs.md`, `stories.md`, `decision-log.md`;
- номер единицы `<КЛАСС>-<NN><NNN>` (`FR-1004`), основание единицы называет `BR` и запись
  журнала (`D-3`);
- журнал - таблица «что решено | кто принял | отклонено | цена | где норматив»; отменённая запись
  помечена «Отменена, заменена D-N»; черта ревизии `--- набор допущен ... ---`;
- снятая единица остаётся в тексте с пометкой «*Снято (D-N).*» (`FR-1005`).

| Фича | Что в ней | Для кейса |
|---|---|---|
| 01 начисление | `FR-1004` 18 месяцев (D-3, пересмотр отменённой D-2 - 24 месяца); `FR-1007` - та же норма словами «полтора года», основание D-3; `ST-1002` AC-1 - дата сгорания по 18 месяцам; `FR-1006` отзывы (D-5), на нём `ST-1003`; `NFR-1002` - API начисления, списания и выписки 500 мс p95 | K0, K1, K4, K5 |
| 02 списание | `FR-2002` - оплата баллами недоступна при подарочном сертификате; счётчик `02.FR` = 2004 | K2, K3, K4 |
| 03 уровни | основания `FR-3001`-`FR-3003` ссылаются на D-1..D-3, `decision-log.md` нет и в истории не было - утрата | K6 |

## Wallet (`alien`)

Требования лежат в `documentation/requirements/<фича>/requirements.md`, решения - `decisions.md`
рядом, номера `PH-N`, `CB-N`, решения `Р-N`; `.docs_layout` и счётчика нет. Корневой `README.md`
ссылается на оба файла требований. Кейс N2.

## Ключ

Засчитывается применение в выходе (дифф и ответ). «Провал» по клетке - нарушение, названное в клетке.

| Кейс | Поручение (кратко) | Единицы | Верно | Провал |
|---|---|---|---|---|
| K0 | сколько живут баллы и почему | чтение журнала; кейс «ничего не менять» | ответ: 18 месяцев, D-3 (пересмотр D-2); рабочее дерево не тронуто | названо 24 месяца или D-2 как действующее; правка любого файла |
| K1 | решение: сгорание через 12 месяцев | запись до числа, номер в основании, пересмотр, зависимые по номеру, род изменения, правка против новой, обход не в артефакт, один журнал | новая запись в журнале 01 (решение, кто, задето); D-3 помечена отменённой со ссылкой на новую; `FR-1004` правлен на месте, основание - новая запись; `FR-1007` правлен (12 месяцев / год); `ST-1002` AC-1 правлен либо назван задетым | `FR-1004` без записи в журнале; D-3 не помечена; `FR-1007` не тронут и не назван; заведён новый `FR` рядом с `FR-1004`; раздел-предъявление обхода («дельта», «что задето») в `srs.md`; второй журнал рядом с другим файлом |
| K2 | доля покрытия баллами неизвестна | открытый пункт записью, номер из счётчика, слаг фичи по теме, класс в одном месте | новый `FR-2005` в `02-points-redemption/srs.md`, `.req_counter/02.FR` = 2005; доля не выдумана либо принята допущением, помеченным открытым; открытый пункт - записью в журнале 02 (что неизвестно, чей ответ), единица ссылается на неё; пункт назван в ответе | доля - числом без записи и пометки; неизвестное только пометкой «TBD/уточнить» в тексте, журнал молчит; номер не 2005 либо счётчик не записан; новая папка фичи; отдельный файл под одну единицу |

| K4 | API списания 300 мс p95 | дубль вне своей фичи, совпадение ключа - находка | ответ называет `NFR-1002` (500 мс, фича 01) как пересечение и выносит выбор владельцу; новая мера допустима только вместе с этой находкой | новая мера без упоминания `NFR-1002`; `NFR-1002` правлен молча |
| K5 | отказ от баллов за отзывы | снятие с пометкой, запись решения, номер не переиспользуется | `FR-1006` остаётся в тексте с пометкой «снято» и ссылкой на новую запись журнала; D-5 помечена отменённой либо новая запись называет её; `ST-1003` помечена или названа задетой | `FR-1006` удалён; снятие без записи в журнале; `ST-1003` не тронута и не названа |
| K6 | решение: «Золото» от 50 000 руб. | утрата объявляется, восстановление не по памяти | ответ называет утрату журнала фичи 03 (основания ссылаются на D-1..D-3, файла нет); основания задетых единиц - «поднять заново» или списком к владельцу; D-1..D-3 не воссозданы как решения | журнал 03 заведён с новым решением, утрата не названа; D-1..D-3 воссозданы из текста требований как решения |
| N1 | новая фича: реферальная программа | дефолт имени, слаг, имя без статуса, номер фичи и блок из счётчика | `docs/requirements/04-<слаг>/brd.md`, `BR-4001`..; `.req_counter/feature` = 04, `04.BR` - последний номер | имя файла со статусом, версией или датой; номер фичи не 04; `BR` вне блока 4000; файл на единицу |
| N2 | новая фича в Wallet | занятый корпус диктует раскладку, чужое не переносится | `documentation/requirements/<слаг>/requirements.md` в форме соседей; существующие файлы не перенесены и не переименованы | дерево `docs/` по конвенции каталога рядом с `documentation/`; перенос или переименование существующих файлов |

Мины вне клеток, судятся во всех кейсах с записью: в журнал пишется только решение, допущение,
открытый пункт - не ход работы («прочитал», «обновил файл»); журнал фичи один.
