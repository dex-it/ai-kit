# RFC-0008 Redis Streams для order-events: сначала параллельная доставка

Автор: команда orders. Статус: на согласовании.

## Проблема и цель
Очередь `order-events` на RabbitMQ обслуживается вручную: два человека, обновления кластера дважды в год занимают по дню. Цель - убрать отдельный кластер брокера, не потеряв гарантию «каждое событие обработано хотя бы раз». Не делать: ничего не меняется - расходы остаются, срок поддержки RabbitMQ 3.12 - до 2027-06.

## Альтернативы
| Вариант | Доставка | Эксплуатация | Решение |
|---|---|---|---|
| RabbitMQ как есть | at-least-once | кластер, 2 дня/год | запасной |
| Redis Pub/Sub | at-most-once, без хранения: при разрыве подписчика события теряются | нет кластера | отклонён: audit-sink и billing-worker не терпят потерь |
| Redis Streams + consumer groups, `XACK` | at-least-once, хранение с `MAXLEN`, pending-список | Redis Sentinel уже есть | выбран |

## Было - стало
| Сценарий | Было (RabbitMQ) | Станет (Streams) | Риск |
|---|---|---|---|
| Потребитель упал до ack | сообщение вернётся, до 5 повторов | остаётся в pending, `XAUTOCLAIM` через 60 с | обработчики идемпотентны по `event_id` (проверено в billing-worker, mailer, audit-sink) |
| Пик 300 событий/с | очередь растёт | `MAXLEN ~ 100000` покрывает 5+ минут простоя | переполнение вытеснит старые - алерт на pending > 50000 |
| Потеря Redis-ноды | quorum queue переживает | Sentinel failover, возможна потеря последних записей (асинхронная репликация) | `WAIT 1`, критичные события дублируются в outbox-таблицу до `XACK` |

## Потребители и совместимость
Потребители перечислены в `docs/services.md`: `billing-worker`, `mailer`, `audit-sink` - все три переводятся, контракт события не меняется (`event_id`, `type`, `payload`). Параллельная доставка: две недели публикуем в оба брокера, сверяем счётчики.

## Откат
До отключения RabbitMQ - переключение флагом `events.broker`; после - 4 часа на восстановление из outbox.

## Вне рамок RFC
Миграция историй и очереди `dead-letter`, безопасность доступа к Redis, нагрузочное тестирование - отдельными задачами OB-12, OB-13, OB-14.

## Оценка
Риски приемлемы, блокирующих вопросов нет.
