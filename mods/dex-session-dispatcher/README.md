# dex-session-dispatcher

Одно окно для всех ваших сессий Claude Code.

Если вы запускаете Claude Code в нескольких окнах терминала или отдаёте задачи в фон, довольно скоро теряешь, где что идёт: какая сессия работает, какая давно ждёт вашего ответа, какая закончила. Мод собирает их в один список прямо в Claude Code: видно состояние каждой, сколько занято в контексте и сколько токенов ушло, что у неё в плане, какие навыки и субагентов она вызывала. Отсюда же можно начать новую сессию, отправить сообщение любой из них, прочитать её вывод, остановить или удалить.

Это **мод** - плагин на function hooks: TypeScript, который исполняется внутри Claude Code. Писался для того, кто видит это впервые: в панели слова вместо технических статусов, у каждого состояния есть подсказка, что делать дальше, на пустом месте стоят три шага, а опасные кнопки сначала переспрашивают.

## Быстрый старт

1. Установить мод (см. «Установка») и открыть Claude Code.
2. Набрать `/sessions`. Откроется панель со списком всех сессий на этой машине.
3. В поле «Новая сессия» описать задачу одной-двумя фразами и нажать Enter. Сессия стартует в фоне, а вы продолжаете работать здесь.
4. Следить за списком. **«Ждёт вас»** - сессии нужен ваш ответ или разрешение на действие. Нажмите на её имя, затем «как открыть»: мод покажет команду, которой её открыть в отдельном окне терминала.
5. Когда сессия закончила, откройте её, прочитайте итог и удалите, если она больше не нужна.

Если сессия ждёт вас, а панель закрыта, над полем ввода появится строка «Сессий ждут вас: N» с кнопкой «открыть список».

## Что видно

В списке на каждую сессию:

- имя и состояние словами: **ждёт вас**, **упала**, **работает**, **свободна**, **готово**, **остановлена**. Сначала идут те, кому нужен человек;
- заполнение контекста полоской и процентом: чем ближе к 100, тем скорее сессия начнёт терять начало разговора;
- где она запущена (фоновая или в окне терминала) и в каком каталоге.

В подробностях сессии:

- тема, модель, когда запущена, расход: контекст и токены;
- план: шаги и сколько из них сделано (если сессия ведёт список шагов), иначе заголовок принятого плана;
- последнее задание и последний ответ;
- вызванные навыки (по числу вызовов) и запущенные субагенты;
- переписка с другими сессиями: что она отправила соседям и что получила;
- связанные pull request, если она их открывала.

## Что можно сделать

| Действие | Кнопка в панели | Команда |
|---|---|---|
| Открыть или закрыть панель | - | `/sessions` |
| Список текстом (читает и модель) | - | `/sessions list`, `/sessions status` |
| Посмотреть сессию подробно | имя в списке | `/sessions 2`, `/sessions имя` |
| Начать новую в фоне | поле «Новая сессия» | `/sessions new [--name имя] [--dir каталог] задача` |
| Отправить сообщение | поле в подробностях | `/sessions say 2 текст` |
| Прочитать вывод | «что вывела» | `/sessions log 2` |
| Как открыть в этом терминале | «как открыть» | `/sessions open 2` |
| Остановить (разговор сохраняется) | «остановить» | `/sessions stop 2` |
| Удалить без возврата | «удалить» | `/sessions remove 2` |
| Перейти к соседней | ‹ и › | `/sessions next`, `/sessions prev` |
| Законченные, только этот проект | кнопки под списком | `/sessions finished`, `/sessions here` |

Сессию называют номером из списка (`2`), именем целиком или его началом, началом id. Если под названное подходит несколько сессий, мод перечислит их и попросит номер, а не выберет первую. Остановка и удаление требуют подтверждения: кнопка меняет подпись на «нажмите ещё раз», вопрос снимается через шесть секунд. Текущую сессию отсюда остановить нельзя.

Всё, что показано в панели, доступно и текстом: команды печатают то же в транскрипт, так что модель видит ровно то, на что смотрите вы.

### Готовые задачи

Если рядом установлен [dex-auto](../../plugins/auto/dex-auto/README.md) с командой `/dex-auto:onboard`, под полем появится кнопка «Подготовить проект к работе с агентами»: она запускает в фоне подготовку проекта (корпус документации, порядок работы в CLAUDE.md, перечень готовности репозитория). Нет команды - нет и кнопки.

## Требования

- Claude Code 2.1.287 или новее: с этой версии моды включены без переменных окружения. Проверено на 2.1.303.
- `claude` доступен в `PATH` (иначе настройка `claudeBinary`).
- macOS или Linux: транскрипты читаются командой `tail`. На Windows нужна среда, где она есть (Git Bash, WSL); без неё список и действия работают, а расход и план показываются как «неизвестно».
- Панель мода сама не откроется на узком терминале (меньше 144 колонок); открытая вами командой `/sessions` работает от 110.

## Установка

```sh
claude plugin install dex-session-dispatcher@dex-claude-marketplace
```

Попробовать без установки, из клона каталога:

```sh
claude --plugin-dir mods/dex-session-dispatcher
```

## Настройки

Меняются в `/config`.

| Настройка | По умолчанию | Что делает |
|---|---|---|
| `refreshSeconds` | 10 | Как часто мод читает список и транскрипты. Минимум 5 |
| `contextWindow` | 0 | Окно контекста для процентов. 0 - угадать по занятому: до 200 тысяч - окно в 200 тысяч, больше - миллион. Если у вас окно в миллион, а сессия занимает меньше 200 тысяч, задайте 1000000 |
| `permissionMode` | inherit | Режим разрешений новых сессий. inherit - как у вас по умолчанию |
| `model` | пусто | Модель новых сессий |
| `claudeBinary` | claude | Команда запуска `claude` |

## Как это устроено и где пределы

В API модов нет вызовов «список сессий», «создать», «остановить», «удалить», поэтому мод собирает возможности из четырёх источников:

- `claude agents --json --all` - какие сессии есть и что с ними;
- транскрипт каждой сессии (`~/.claude/projects/...`, либо `CLAUDE_CONFIG_DIR`) - токены, контекст, план, навыки, субагенты, переписка;
- `claude --bg`, `stop`, `rm`, `logs` - запуск, остановка, удаление, вывод;
- `$.session.send` - сообщение другой сессии.

Отсюда пределы, о которых стоит знать:

- **Формат транскриптов внутренний.** Документация Claude Code просит на него не опираться и обещает менять между версиями. Мод читает его защитно: что не нашлось, показывается как «неизвестно», а не ошибкой. Если после обновления Claude Code расход или план пропали, причина, скорее всего, здесь.
- **Суммы считаются по последним ходам.** Мод читает хвост истории (до полутора мегабайт) и дальше только дописанное, поэтому «токенов израсходовано» - это последние ходы, а не вся жизнь длинной сессии. Процент контекста от этого не зависит.
- **Шаги плана видны, если сессия ведёт их инструментом `TodoWrite`.** Сессия, которая плана не ведёт, показывает только заголовок принятого плана или ничего.
- **Открыть чужую сессию в этом окне нельзя.** Терминал мод отдать не может: он называет команду `claude attach` для фоновой сессии или напоминает, в каком окне открыта обычная.
- **Сообщение доходит до сессий на этой машине.** Получатель вправе настроить приём (`crossSessionInbound`) и отказать; тогда мод покажет причину из ответа. Сообщение от другой сессии не считается вашим разрешением на действия.
- **Фоновая сессия, которой нужно разрешение, встаёт и ждёт.** Это не ошибка: в списке она «ждёт вас». Чтобы такие задачи шли без остановок, задайте `permissionMode` осознанно.
- **Новая сессия стартует в доверенном каталоге.** В нетронутом каталоге `claude --bg` откажется; мод скажет об этом и подскажет открыть там `claude` один раз.
- **Мод ничего не запускает без вашего действия**, кроме чтения: опрос идёт только в интерактивной сессии, в `claude -p` его нет.

## Проверка

```sh
npm run typecheck:mods
npm run test:mods
claude plugin validate --strict mods/dex-session-dispatcher
claude -p "/sessions status" --plugin-dir mods/dex-session-dispatcher
```

Отрисовка панели и кнопок проверяется только в живой сессии.
