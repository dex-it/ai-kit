# DEX AI KIT
> **Нормативный дом правил разработки**: как писать плагины, ревьюить, проверять перед коммитом - не обзор. Обзор проекта (концепция, 3 уровня, структура папок, тех-стек, MCP по ролям) - [README.md](README.md), конфигурация MCP - [mcp/README.md](mcp/README.md); устройство фреймворков - `docs/*_FRAMEWORK.md`.

Источники истины: `.claude-plugin/marketplace.json` - каталог всех плагинов; `tools/validate-*.js` - валидаторы (цепочка целиком - `npm run validate`); `docs/` - фреймворки и гайды; `.claude/rules/` - path-scoped правила репозитория. Выпуск и нумерация `#N` двух репозиториев - `.memory-bank/INDEX.md` (по требованию, без `@`).

## Конвенции

### Именование
- **Skills**: `dex-skill-{name}`. Для стек-специфичных skills `{name}` = `{стек}-{тема}` (`dotnet-ef-core`, `ts-nodejs-api`, `python-pytorch`) - единый стековый префикс обязателен для by-stack loading (см. ниже). Язык-нейтральные skills (docker, solid, ddd) префикса стека не несут.
- **Skill, производящий документ по стандарту**: `dex-skill-{предмет}-{стандарт}` (`system-requirements-29148`, `architecture-definition-42010`, `verification-planning-29119`, `use-cases-cockburn`, `bdd-gherkin`). Имя отвечает на «какой документ и по какому стандарту» до открытия файла. Стандарт или метод в имени каталог несёт и сейчас (`solid`, `ddd`, `clean-architecture`), но там имя стандартом исчерпывается; **порядок частей задаётся этим правилом впервые и задним числом не применяется**. Три границы: **предмет первым, стандарт вторым** - имена этапов взяты от процессов стандарта, чтобы вставка этапа посередине не переименовывала соседей ([NORMS.md](docs/pipelines/analytics/NORMS.md), раздел 7), и перестановка эту мотивировку ломает; **предмет без стандарта суффикса не получает** - приписать номер там, где стандарта нет, значит соврать об опоре; **оракулы качества под правило не подпадают** - их имя закреплено отдельным пунктом этого списка, на него завязан реестр «тип -> оракул», а стандарт у оракула указан внутри, опорой проверок.
- **Specialists**: `dex-{domain}-{role}` или `dex-{name}-specialist`
- **Bundles**: `dex-bundle-{role}`
- **Utilities**: `dex-{name}`
- **Mods**: `dex-{name}`, как у утилиты. Имя классы не различает - различают дерево (`mods/` против `plugins/`) и `category` записи каталога; признак выводится из содержимого, и дом правила - [MOD_FRAMEWORK.md](docs/MOD_FRAMEWORK.md).
- **Skill-оракул качества артефакта**: `{тип}-quality` (`requirement-quality`, `requirement-set-quality`, `adr-quality`). Оракул судит готовый артефакт названного типа и даёт вердикт для метки `quality-checks`; конвенция удерживает соответствие «тип -> оракул» именем, а не догадкой. Реестр соответствий - явная таблица в `dex-skill-node-contract:node-contract` («Реестр "тип артефакта -> оракул"»), новый оракул добавляется строкой туда же; тип без оракула закрывается записью `unverifiable` с причиной, не молчанием (`n/a` в `quality-checks` не пишется - п.7 контракта).

#### Имя агента (frontmatter `name`): стек в имени - только у стек-специфичных

Имя плагина-специалиста (директория `dex-*`) и имя **агента** в его frontmatter (`name`) - разные вещи. Правило для `name`:

- **Стек-специфичный агент** (специфика стека живёт в теле артефакта - идиомы языка, библиотеки экосистемы) -> стек в имени: `dotnet-coder`, `dotnet-test-writer`, `dotnet-ef-specialist`, `ts-test-writer`, `ts-fullstack-assistant`. Generic-имя (`coding-assistant`, `test-writer`) для стекового агента запрещено - оно не отличает агента от общего и даёт коллизию при росте стеков (два `test-writer`'а).
- **Общий (языко-агностичный) агент** (стек грузится через skills по реестру, тело нейтрально) -> чистая роль без стека: `debugger`, `bug-fixer`, `security-reviewer`, `mr-reviewer`, `self-reviewer`.

Имя файла агента совпадает с `name`. Rename агента = major bump (директория плагина и `plugin.json` `name` при этом не меняются - `bundle.json` ссылается на директорию, а не на агента).

#### By-stack loading: общий агент грузит профильные skills по реестру

Общие агенты не хранят зашитый список «если .NET -> skill X»: они грузят process-skill `dex-skill-stack-registry:stack-registry`, определяют стек по манифесту и фильтруют available-skills по префиксу `dex-skill-{стек}-*`. Отсюда конвенция репо: **новый стек = новые `dex-skill-{стек}-*` + строка реестра, агенты не правятся**. Механизм отбора и эмпирическое обоснование префикса - [docs/AGENT_FRAMEWORK.md](docs/AGENT_FRAMEWORK.md#by-stack-loading-общий-агент-грузит-профильные-skills-по-реестру).

### Frontmatter агентов

Поля и правила (`skills:`, `allowed-tools:`, `model`) - нормативный дом [AGENT_FRAMEWORK.md](docs/AGENT_FRAMEWORK.md#выбор-модели-model) (чеклист frontmatter + раздел «Стоимость: `model` и `effort`»).

**`model` - потолок, `effort` - override сессии**: вниз - для механической работы, вверх - только с названной в теле причиной, сомневаешься - не ставь. Значения, дефолты, оговорки по моделям и провайдерам - [AGENT_FRAMEWORK.md](docs/AGENT_FRAMEWORK.md#глубина-рассуждения-effort).

**Каскад tools под fact-check.** Агент с фазой Fact Verification (грузит `dex-skill-fact-verification:fact-verification`) обязан нести в `tools` весь каскад: `ToolSearch` **и** `WebSearch, WebFetch`. Нет звена - каскад молча деградирует до latest-доки; ловит `npm run validate:agents` (`factcheck-cascade-incomplete`). Почему именно эти три и что ломается без каждого - [AGENT_FRAMEWORK.md](docs/AGENT_FRAMEWORK.md#reviewer) («Tools для каскада»).

### Frontmatter skills
`keywords` в skills не поддерживается - ключевые слова в `description`; ловит `frontmatter-forbidden`. Форма frontmatter и перечень валидных полей - [SKILL_FRAMEWORK.md](docs/SKILL_FRAMEWORK.md) (там же дата сверки с документацией).

## Структура плагина

**Скилл, потребители которого - только артефакты одного плагина, едет внутри этого плагина** (`skills/<name>/` рядом с `agents/`), а не отдельной записью каталога: отдельную запись пользователь ставит порознь и получает агента без его норм. Адресуется такой скилл полной формой `{plugin}:{skill}` от плагина-владельца, категория записи выводится из содержимого (`agents/` есть -> `specialist`), а замыкание бандла закрывается самим плагином - именем скилла состав не перечисляют, такого плагина нет. Скилл, который грузит хотя бы один артефакт вне плагина-владельца, живёт отдельным `dex-skill-{name}`: внутри чужого плагина он поедет только вместе с ним. Скилл и агент делят пространство имён `{plugin}:{artifact}`, поэтому проверки ссылок различают их перечнем артефактов плагина, не формой адреса.

## Механизмы композиции в Claude Code

**Практические правила:**

- **Skill не загружает другой skill автоматически.** Упоминание `dex-skill-X` в теле SKILL.md его не запускает - только справочная сноска (`> см. dex-skill-X`). Рабочий путь - предписать: тело просит исполнителя (главный поток или агента) вызвать `Skill` `{plugin}:{skill}` явно (прецедент `artifact-review`). Формулировка «загружает / активирует / подключает» без слова «предписывает» / «вызывает `Skill`» - ложь, переписать.
- **Дублирование ловушек между skills - зло.** При пересечении тем оставить содержимое в одном skill, из другого - сноска.
- **Композиция skills - явным вызовом `Skill`.** Исполнитель (агент в своей фазе, либо главный поток, которому это предписано телом скилла) вызывает `Skill` с точным именем `{plugin}:{skill}`; сам факт «оба носителя - skill» композицию не даёт.
- **Связь между специалистами в bundle** - это установка вместе, не runtime-вызов.

## Чек-лист при изменении плагинов

### Принципы содержания

- **Нормативная единица пишется по форме, и у правки есть бюджет.** Тронул нормативную единицу - пишешь новую, переписываешь целиком или правишь существующую - вызови `Skill` `dex-skill-norm-writing:norm-writing` до реза подачи: там форма единицы, бюджет нормы, признак приписки и адрес дома против цитаты соседней нормы. Не вызван - правка не сдана; плагин не загружен (не установлен либо нет `Skill` в `tools`) - дельта объёма тронутого носителя с названной снятой взамен единицей идёт в отчёт, недостижимость дома идёт находкой, и по памяти дом не воспроизводится.
- **Пунктуация в артефактах - ASCII, не Unicode.** Дефолт: `-` вместо `—`/`–`, `->` вместо `→`, `<-`/`<->` вместо `←`/`↔`, `<=`/`>=`/`!=` вместо `≤`/`≥`/`≠`, `...` вместо `…`. Причина: для артефакта-входа модели типографика на качество не влияет, но ASCII токенизируется стабильнее (1 байт = 1 токен; `—` - UTF-8 3 байта, у части токенизаторов 2-3 токена) и даёт единый стиль. Решает консистентность, не экономия. НЕ трогать: кавычки «», box-drawing диаграмм (`│├└─`), эмодзи-статусы, `№`, надстрочные индексы, `×`, Unicode-примеры внутри `inline code` (там символ - предмет показа, не текст). Миграция **пофайловая**: не сквозняком по репо за раз, но тронул файл по любой причине - приводишь его к ASCII целиком (не только свои строки). Единица миграции = файл. Нетронутые файлы на Unicode до своей правки - не дефект.
- **Имя артефакта в теле - обязательство поставки, не иллюстрация.** Адрес `{plugin}:{skill}` в теле агента, команды, skill или его `references/` исполнитель читает как «этот артефакт у меня есть, его можно вызвать», поэтому упомянутый плагин обязан ехать в каждом бандле, где едет упоминающий. Отсюда запрет: именем реального плагина не иллюстрируют форму вызова (`{plugin}:{skill}` пишется без «например ...»), не показывают эталон формулировки и не называют дом нормы, который в поставку не входит - всё это адресуется описанием («движок SDLC», «оркестратор зоны»), не адресом. Ссылка на неустановленный артефакт хуже её отсутствия: адрес выглядит валидным, и модель либо молча не находит цель, либо сочиняет её содержимое. Механизировано замыканием бандла (`bundle-not-closed` и соседние правила в `validate-bundle.js`): имя, которого нет в составе, - ошибка.
- **Документ каталога из тела артефакта не адресуется вовсе.** Тело команды, агента и skill (вместе с его `references/`) исполняется в проекте пользователя, а `docs/` каталога в установленный плагин не входит. `docs/` - дизайн-тайм: он нормирует авторство артефактов, не их исполнение. Исход хуже отсутствия ссылки - адрес выглядит валидным, и модель либо молча его не находит, либо сочиняет содержимое. Норма, нужная в рантайме, живёт **в самом артефакте** либо в скилле, который у пользователя установлен (`dex-skill-node-contract:node-contract` и прочие плагины каталога); дрейфующие числа (лимиты размера носителя, минимум активаторов) в тело не переписываются: размер судится **прогоном валидатора** - сработало правило, порог назван в его сообщении; промолчало - носитель в пределах, и число знать не нужно. Тем же правилом адресуется **соседний плагин** (`../<плагин>/README.md`): у пользователя плагины ставятся по отдельности, поэтому сосед называется именем скилла или плагина, не путём. Механизировано двумя правилами (error) во всех трёх валидаторах: `catalog-docs-link` на адрес документа каталога в любой форме записи (матчер - `docs/VALIDATOR_RULES.md`), `link-escapes-plugin` на ссылку, выводящую за корень плагина. Подъём внутри своего плагина законен - решает разрешённый путь, а не число `../`. Правило НЕ применяется к пути **в проекте пользователя** (`docs/discover/README.md` как выход агента, `docs/brd/payments.md` как вход): такого файла в `docs/` каталога нет, адресуется чужой корпус. Из-под правила выведены и `docs/product/`, `docs/domain/` - эти два каталога `dex-skill-project-docs-map:project-docs-map` раздаёт пользователю под корпус уровня 0 **его** проекта, поэтому путь под ними именует чужой документ, а не наш. Исключение - артефакты автора каталога: плагины из `authorOnly[]` бандла `dex-bundle-market-editor` исполняются только в локальном клоне, где `docs/` лежит рядом, и правилу не подлежат; плагин замыкания, который едет пользователю бандлом роли, в `authorOnly[]` не ставится (`author-only-in-user-bundle`).
- **Адрес документа каталога из README плагина - абсолютный URL, не относительный путь.** README едет в установленный плагин вместе с ним, `docs/` - нет, поэтому относительный `docs/X.md` из него указывает в чужой проект. Форма: `https://github.com/dex-it/ai-kit/blob/main/<путь>`, при указании на раздел - с якорем; отступы вверх ловятся `rg '\]\(\.\.[^)]*\)' plugins mods`. `main` здесь не произвольная ветка, а канал поставки: установка **без `ref`** берёт дефолтную ветку («`ref` - Optional. Git branch or tag (defaults to repository default branch)», [plugin-marketplaces](https://code.claude.com/docs/en/plugin-marketplaces), сверено 28.07.2026). **Синхронность носителя и цели - условие, а не свойство: форма верна, пока `main` получает `develop` целиком.** Частичный перенос носителя без его документа даёт ложно-валидный адрес; проверка - `git grep -o 'blob/main/[^)]*' origin/main -- plugins`, каждая цель существует в том же снапшоте **вместе с разделом, если адрес несёт якорь** (файл на месте, а раздела в нём нет - тот же исход, и `git cat-file -e` его не ловит). Якорь ищется в двух формах сразу - HTML-тег `<a id="...">` и заголовок markdown; проверка по одной форме даёт ложное срабатывание, в каталоге есть обе. Пин поддержан («To pin to a branch or tag, append `@ref`...», там же), и у поставившего каталог как `...@develop` синхронности нет вовсе. Файлы за пределами `plugins/` (корневой `README.md`, `install-bundle/`, сам `AGENTS.md`) правилом не покрыты - читаются в клоне репозитория, где `docs/` рядом. Голое имя пути в backticks разрешаемого адреса не обещает и правилом не покрывается.

- **Имя сущности корпуса берётся из словаря, новое имя заводится строкой в нём.** Дом имён - [docs/domain/domain-model.md](docs/domain/domain-model.md). Пишешь артефакт или норму - имя берёшь оттуда; термина в словаре нет - строка заводится **тем же изменением**, что вводит имя, а не следующим: к моменту, когда термин попал в текст, значение уже решено автором, а через правку оно восстанавливается по памяти. Имя, помеченное в словаре `к вытеснению`, в новом тексте - дефект, не стилистика: два имени одного смысла расходятся молча и ловятся только сплошным ревью корпуса. Термин под открытым расхождением `D-N` до решения законен обеими сторонами - выбор делается решением, не правкой на месте. Перечень заведённых имён (без значений) лежит в стартовом контексте каждой сессии и субагента - `.claude/rules/terminology.md`, генерируется из словаря (`npm run sync:terminology`, синхронность держит `npm run validate`); за значением, домом и «не путать с» идёшь в словарь. Употребление имени судит ось «Терминология» в `dex-skill-artifact-review:artifact-review`; валидаторы артефактов словарь не читают, кроме `tools/validate-terminology.js`: имя `к вытеснению` в тексте каталога ловит `ousted-name`, дом строки словаря - `home-unresolved` и `home-term-absent` (все error; область, исключения и форма адреса - `docs/VALIDATOR_RULES.md`). Закрытый перечень под именем без дома заводит строку словаря тем же изменением; перечень, уже живущий в доме соседнего термина, сверяется с ним.
